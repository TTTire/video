# 文档带读元素族设计（文件高亮风格）

> 用户 2026-11-13 确认。风格出处：小lin说「文件重点高亮」+ Remotion 复刻实验（[aitntnews 文章](https://m.aitntnews.com/newDetail.html?newId=24076)，9 组特效）。用途：讲到研究材料、文章、报纸、论文原文时，用「文档页滑动 + 黄底高亮 + 聚焦放大 + 翻页」渲染。实现挂在管线优化方案的阶段 5（视觉升级）。

## 1. 风格定义（用户描述 + 检索确认）

- 黑底（或黑底白线条），文档页是画面主体
- 页面上下滑动，跟着口播定位到相关段落
- 黄色半透明高亮压住关键句（唯一强调色）
- **轻微放大聚焦**：高亮句所在区域轻微放大（约 1.08–1.15 倍），页面其余部分压暗/虚化（用户补充）
- 页与页之间用翻页转场
- 专业感来源：原始材料感（有据可查）+ 高亮锚点（视线钉死）+ 动效克制（只有滑、翻、聚焦三种）

## 2. 新增元素规格

### document（文档带读）

视觉与动效序列（按口播点逐条触发）：

1. 页滑入：文档页从下往上滑入（ease），落位
2. 定位：随口播滑到目标段落
3. 高亮：黄底块渐显压住目标句（可做「扫过一行」的擦入）
4. 聚焦：以高亮句中心为 transformOrigin 轻微放大（1.0 → 1.08–1.15），页面其余区域压暗（dim 0.55–0.7）+ 轻微虚化
5. 换页：翻页转场（见 pageflip）

布局：

- 横屏 16:9：文档页在画面右侧/中央，左侧留字区（和现有「字在左、主体在右」的留白习惯一致）
- 全屏模式（`pos: full`）：整屏只有文档，高亮句是画面里唯一强调

规则（与 AGENTS 兼容）：

- document 元素内允许出现原文文字——这是引用原文，不是「图中带字」的违例；但引用的句子必须与发布清单「事实核对」条目一一对应（字段里写 fact 号）
- 页面截图不带第三方水印 / logo / 装饰页码以外的元素；有就裁掉或压暗
- 整页展示时，非引用部分一律压暗+虚化——既聚焦，也避免整页长文的版权问题
- 一期 1–3 处，和照片铺底段落交替；不整期都是文档（会变 PPT 讲解）

### pageflip（翻页）

- **硬翻（2D）**：页面绕中线左右翻（线性蒙版翻转，剪映「蒙版翻页」同原理），约 0.5s，配 whoosh。Remotion 实现简单，先做这个
- **软翻（3D）**：rotateY 90° 换页 + 光影；文章实测 3D 纵深感是 Remotion 弱项（5–6 分），后补
- 变体：**标题翻落**——标题卡片从画面上方翻下来（文章第 9 组），可给章节卡用

### pyramid（分层信息图）

- 文章第 1 组「种姓制度金字塔」：N 层渐变层级图，每层有名称/翻译/描述/小图标，逐层从下往上弹出
- 用在哪：收入阶层、财富分布这类「分层」的经济学场景
- 图标用代码画的几何形/简笔，不用版权素材

**净增只有 2 个元素**（document、pyramid）+ 1 个转场（pageflip），其余全是现有元素的变体增强（photorow skin、units 变体、tagwall 布局、graph 光效）。符合「元素少而语义固定」的既有原则。

**对现有元素的增强一律加开关、默认关**：photorow 徽章 skin、units 百分比变体、graph 连线光效、给章节卡用的「标题翻落」，不写开关时渲染结果要和现在逐帧一样（graph 已经用在已发布的 ai03，章节卡每期都有）。只有新期按需打开。

## 4. photo.json 字段草案

```json
{
  "type": "document",
  "src": "doc01.png",
  "pos": "right",
  "quotes": [
    {"text": "原句……", "box": [0.06, 0.42, 0.88, 0.06], "at": 0, "till": 2, "zoom": 1.12, "fact": 3}
  ],
  "flip": "hard",
  "dim": 0.6,
  "blur": 2
}
```

- `src`：页面截图（入库用 import_photos 同流程，单独 `doc/` 目录）。宽度 ≥ 页面在画面里的显示宽度 × `zoom`，否则放大后字是糊的；全屏（`pos: full`）一律 ≥ 2560，PDF 按 ≥ 2560 宽导出，别拿小截图放大
- `box`：高亮句在页面截图上的归一化坐标 [x, y, w, h]
- `zoom`：聚焦放大倍数，默认 1.1，范围 1.05–1.15；不写则只高亮不放大
- `fact`：发布清单「事实核对」条目号，**必填**——校验时双向核对（引用句 ↔ 来源链接）
- `pyramid`：`{"type": "pyramid", "layers": [{"name": "…", "en": "…", "desc": "…", "color": "…"}], "at": 1}`
- `tagwall`：`{"type": "tagwall", "tags": ["央行", "首饰", "科技", "投资"], "strike": [2], "at": 0}`

## 4b. 尺寸约束（tagwall 专条）

复刻版四宫格卡片偏小，本版规则：

- tagwall 是**画面主体**：四张卡 2×2 占满画面中区，不缩在角落当装饰
- 每张卡宽 ≥ 780（与数字卡同级），标签字走 `h` 档（88/112），不做小字标签
- 竖屏手机上看，标签字高不小于画面宽度的 4.5%
- 与大字叠字不同屏：tagwall 出场时该场景不放大字，避免两套字打架
- 逐张入场（依次飞入 + 轻回弹），被否的标签盖 X（用 strikeAt 同款动画），一张一期最多出现一次

## 5. 校验规则（validate_ep 新增）

- document 的每条 quote 必须有 `fact` 号，且该号存在于发布清单「事实核对」
- document 的 `src` 必须已入库（占位图不算）
- 高亮句 `box` 必须在页面截图范围内；`zoom` 超范围报 warn
- 一期 document 场景数 ≤ 3，超过 warn（防止变 PPT）

## 7. 素材需求与来源（用户可找矢量图/素材）

入库方式照音效库的模式：素材放进 `工具/图标库/`，实现阶段加 `import_icons.py` 统一裁切/命名/进工程。

| 素材 | 用途 | 规格（找素材时按这个） | 优先级 | 来源建议 |
|---|---|---|---|---|
| 线条图标集（人、钱币、房子、工厂、芯片、箭头、天平、队列……约 20–40 个） | pyramid 层级图图标、photorow 徽章、tagwall 角标 | **单色** SVG 或透明底 PNG ≥ 512；线宽统一；无文字；**可商用**；整组风格统一（线条风，呼应 document 的黑底白线审美；引擎能改色） | 高 | Lucide / Tabler / Phosphor / Feather（MIT 或 Apache 开源图标集，可直接商用）；iconfont 注意个别图标授权限制 |
| 纸纹 / 纸面纹理 | document 页面底色、paper 卡质感增强 | 无缝平铺 JPG/PNG ≥ 1024，灰度，可商用 | 低（代码噪点可替代，有素材更高级） | Pixabay 纹理类（免费可商用） |
| 实物小图（钞票堆、硬币堆） | units 变体 | 透明底 PNG ≥ 1024，无文字、无品牌标识 | 中（也可用即梦出图代替，风格更贴照片铺底） | 用户出图或 Pixabay |

找齐后放到 `工具/图标库/`（参照 `工具/音效库/` 的模式），实现阶段写 `import_icons.py` 入库。
