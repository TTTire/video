# 画面与素材清单：格式

写在发布清单的 `## 画面与素材清单` 下面，分三部分：全局风格、分场景表格、出图清单（出图清单的最后一段是卡内小图）。叠字该怎么写（字号和字数、字体、卡片、字效）见 SKILL.md 的「画面规则」。

样例：`已完成/9-100-供给定律-旧手机为什么突然值钱了/…-发布清单.md`（《100 个经济学原理》）、`已完成/AI时事04-刷题为什么突然没用了/…-发布清单.md`（《AI经济学》）。第 6 期发布清单是旧格式（分场景表第 3 列是「起始句」），别照抄。

## 1. 全局风格

**先定本期视觉方案，再写提示词。** 栏目固定不变的是：章节卡结构、音效语言、底部字幕位、**标题字体得意黑**（左上角标 2026-10 起已经取消，见 SKILL.md「两个栏目」）、"写实照片铺底 + 大字 + 代码图表"这个大框架。其余五项每期从本期内容出发重新选，**和上一期相比至少换 3 项**（上一期的方案写在它发布清单的 `STYLE_DNA` 注释里，先去读）：

| 维度 | 可选 | 怎么选 |
|---|---|---|
| 文字母版 `layout` | `topleft` 左上大字 / `right` 右侧右对齐 / `center` 居中 / `bottom` 底部字幕带式（**字幕得放顶部**，先问用户） | 看图的留白习惯：主体多在右 → topleft；主体多在左 → right；氛围图多 → center |
| 强调色 `gold` + 正/负色 `teal` `coral` + 压暗色 `bg` | 从本期照片里取：夜景冷调 → 香槟金 `#D9C49C` + 冷蓝底 `#070B14`；暖光门店 → 陶土橙 `#E07B45` + 暖黑 `#0B0907`；白天/自然 → 墨绿、赭石… | 照片入库后看一眼主色，强调色要和照片里的光源色呼应 |
| 照片处理 `tint` / `letterbox` / `grain` | 统一罩色（冷蓝、暖褐、青灰）、2.35:1 黑边、胶片颗粒，任意组合或都不用 | 电影感 / 纪录感 / 干净杂志感，三选一 |
| 入场 `enter` | `blur` 柔切（默认）/ `cut` 硬切 / `slideL` 横推 / `zoom` 缩放 | 节奏快、短句多 → cut；舒缓 → blur |
| 图表语言 | 柱状 / 阶梯 / 表格 / 折线 / 对比卡 | 跟着数据的形态走，但别和上一期用同一种 |

写进发布清单时，先用一句话说清这期"看起来像什么"，再附一行机器可读的注释（脚本会把它写进 photo.json 的 `style`）：

```markdown
- 本期视觉方案：冬夜橱窗的冷调，字像奢侈品广告——香槟金、冷蓝罩色、2.35:1 黑边、硬切。和第 6 期（暖黑 + 陶土橙 + 左上大字 + 柔切）换了配色、照片处理、入场 3 项。
<!-- STYLE_DNA layout=topleft gold=#D9C49C coral=#C9545A teal=#9DB9CF bg=#070B14 dim=#B9C0CC tint=#1B2A44 tintOpacity=0.3 enter=cut letterbox=1 grain=0 badge=0 scale=v2 textEnter=fade cardSkin=tactile -->
```

`STYLE_DNA` 能写的键：`layout`；配色 `gold` `coral` `teal` `bg` `white` `dim`；`tint` `tintOpacity`；`enter`；`letterbox` `grain` `badge`（写 1 / 0）；`scale`；`textEnter`；`cardSkin`；`sfx`。

**新期最后四项照抄 `badge=0 scale=v2 textEnter=fade cardSkin=tactile`。** `scenes_from_checklist.py` 会按 STYLE_DNA **整体重写** photo.json 的 `style`：

- `badge` `scale` `sfx` 没写，脚本会自动补上新期默认值；
- `textEnter` `cardSkin` 没写，就会退回旧样子（飞入 + 扁平卡）；
- 在 photo.json 里手加的 style 项（比如 `cards`），重跑一次就没了。

所以想改风格，一律改 STYLE_DNA。

效果对比参考：本目录的 `style-compare-ep7.jpg`（上：第 7 期实际版；下：同一内容换一套方案）。

然后是提示词和规格，固定写法（除非用户要换风格）：

```markdown
### 全局风格
- 风格：写实电影感摄影，夜景 / 室内暖光、浅景深、35mm；**画面里不要有任何文字**（招牌、数字、价签都不要，字由代码加）
- 一致性：先出 1 张主场景定调，之后所有同场景的图用它垫图；人物服装、关键道具（本期：___）在所有图里保持一致
- 规格：16:9，宽 ≥ 2560（即梦 2752×1536 直接可用），JPG/PNG，文件名带编号如 `S01.jpg`
- 提示词前缀（每张都拼在前面）：`写实摄影，电影感，<本期场景一句话>，<灯光>，浅景深，35mm 镜头，<人物设定>，画面无文字，16:9`
- 留白：每张图注明文字放哪一侧，那一侧构图留 35–45% 相对干净的区域（代码会压暗，不必纯色）
```

## 2. 分场景表格

列是固定的，脚本按列的位置解析：

```markdown
### 分场景

| # | 场景 id | 起始要点 | 这段在讲什么 | 图 | 叠字 | 环境声 |
|---|---|---|---|---|---|---|
| 01 | shop | 0.1 | 晚七点排队，老板再叫一个人 | S01 | 「门口排了十几个人」「老板：再叫一个人 +1」「这下总该快了吧？」 | 街道夜晚 |
| 05 | chapter | 1.0 | 第 1 章 章节卡 | — | — | — |
| 06 | bars | 1.1 | 1→5 人出杯 30/60/80/85/87?，柱状图 | S08 S02 | 柱状图（代码）「第四个人：只多了 5 杯」 | — |
```

- **场景 id**：小写英文，之后就是代码里的名字。章节标题行固定写 `chapter`。
- **起始要点**：讲稿卡的要点 id（`章.序`：开头从 `0.1` 起，第 N 章从 `N.1` 起）。
  - 第一行必须是 `0.1`。
  - 章节卡行写 `1.0` / `2.0` / `3.0`，场景 id 写 `chapter`，三章都要有；章节卡的下一行必须从 `N.1` 开始。
  - 讲稿卡一增删要点，后面的 id 就会变，场景表要跟着改（脚本会报不存在的 id）。其他要跟着改的地方见 SKILL.md「讲稿卡增删要点之后」。
- **切分粒度**：一个场景 = 一个画面主体，从它的起始要点讲到下一个场景的起始要点之前，通常 1–3 条要点、10–30 秒。
  - 一段话里数字连续变化（柱状图、表格），可以放在一个长场景里。
  - 场景只能从要点开头开始。想在一条要点中间换画面，就在讲稿卡里把它拆成两条。
- **图**：可以写多张：第一张是底图，第二张在场景中途淡入切换（场景有 2 条以上要点时从第 2 条换，只有 1 条时讲到 6 秒换）。可以复用别的场景的图。纯文字卡写 `—`。
- **叠字**：每条「」一句，按顺序挂到场景内的要点上：第 i 条叠字 → 第 i 条要点；多出来的挂在最后一条上，每条再晚 3 秒。图表写「柱状图（代码）」这类说明。叠字不是字幕，是**提炼**：短、有数字、有对比。视觉语言 v2 落地后会改成按类型配字，叠字列也能写展示形式名（见 SKILL.md「禁用清单」末尾，落地前照这里写）。
- **环境声**：只写音效库里已经导入的名字（`工具/video-render/src/sfx-manifest.json` 里的 ambience，现在只有「商场」「街道夜晚」），而且只在开场、金句、结尾这类需要氛围的场景写。
  - 需要别的氛围，就在出图清单后面加一行补音效任务（见下面第 3 节）交给用户，等补完、跑过 `import_sfx.py` 再写进表。
  - 写了库里没有的名字不会报错，引擎会在现有的几条环境声里按位置挑一条，声音和画面就对不上了。

## 3. 出图清单

每张图只写一次：

```markdown
### 出图清单（共 N 张）

先出 **S01**，确认风格后用它垫图出其余。

| 编号 | 画面 | 文字放哪侧 | 用在 |
|---|---|---|---|
| S01 | 夜晚奶茶店外景，暖黄灯光，门口一条十几人的队伍，透过橱窗能看到吧台里 3 个店员，老板站在门边招手 | TW | 01, 23 |
| S02 | 队伍中段特写，年轻人侧脸看手机，主体靠右 | TL | 02, 09 |
```

画面描述要能直接当提示词的主体：机位（外景 / 内景平视 / 俯视 / 特写 / 顾客视角）、谁在干什么、关键道具在哪、情绪。镜像构图的一对图（分屏用）标 `S20A / S20B`，并写明主体各靠哪一侧。

**「文字放哪侧」写画面区域名**（3 列 × 3 行：`TL TC TR / ML MC MR / BL BC BR`，整行居中用 `TW MW BW`）。这一列有两个用处：给用户出图时提示留白，也是脚本填 `box` / `grad` 的依据。出图、填 JSON、看拼图提意见都用这一套词，不用再把"上 1/3"翻译成像素。详见 `photo-json.md`「画面区域」。

- 一张图只写一个区域名。写两个（`TL+ML`）时脚本只认第一个；真要组合区域，在 photo.json 里手写 `boxes`。
- 脚本按区域填的 `grad` 有两处要手改，见 SKILL.md「2. 填 photo.json」。

**卡内小图**：实物卡（photocard / photorow / graph）用的小图，在出图清单最后单独写一段「卡内小图」，编号 `C01`…，要求方形、主体居中、无文字，规格见 `photo-json.md`「卡内小图」。

**补音效**：本期要用音效库里没有的环境声时，在出图清单最后加一行，比如 `补音效：ambience-办公室（键盘、空调低鸣、偶尔椅子声）`，交给用户按 `工具/音效库/补充音效清单.md` 去找。
