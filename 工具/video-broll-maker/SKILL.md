# 像素呼吸 B-roll 动画轨

渲染工程在 `工具/video-render/`（Remotion，命令都在这个目录下运行）。工作区根目录：

| 系统 | 工作区根目录 | Python 命令 |
|---|---|---|
| macOS | `/Users/tttire/Documents/工程队/视频选题` | `python3` |
| Windows | `E:\视频脚本` | `python` |

下文命令一律用相对路径（`cd 工具/video-render`），两套系统都能直接跑；只有 Python 命令按上表区分。第 6 期是完整样例：
发布清单 `已完成/6-100-边际报酬递减-人多了为什么没快多少/…-发布清单.md`，场景表 `工具/video-render/src/ep6/photo.json`，图表 `src/ep6/custom.tsx`。

成片是什么：1920×1080 / 30fps、和用户口播等长、**只有音效没有配音**的动画轨。字幕和 BGM 用户在剪映加，所以画面文字压在上 2/3，底部留字幕位。

出镜怎么合：两条路，用户选——
1. **用户自己叠**：拿 B-roll 动画轨和 A-roll 在剪映里从 0 秒对齐，想露脸的地方切掉动画轨（第 8 期及以前都这么干）
2. **引擎合**（2026-10-29 起）：用户给对齐 srt 的粗剪 A-roll，photo.json 写 `aroll.cues`（行号 → full / half / bubble），引擎渲出 B-roll + 出镜层的成片，小圆 ⇄ 全屏之间是圆形 iris 切换。A-roll **静音**，人声和字幕仍由用户在剪映加。字段见 `references/photo-json.md`「出镜层」

## 写稿阶段：画面与素材清单

写在发布清单 `## 画面与素材清单` 下，三部分。完整样例见第 6 期发布清单。

### 1. 全局风格

**先定本期视觉方案，再写提示词。** 栏目固定不变的是：章节卡结构、音效语言、底部字幕位、**标题字体得意黑**（左上角标 2026-10 起已取消，见上一节）、"写实照片铺底 + 大字 + 代码图表"这个大框架。其余五项每期从本期内容出发重新选，**和上一期相比至少换 3 项**（上一期的方案在它发布清单的 `STYLE_DNA` 注释里，先去读）：

| 维度 | 可选 | 怎么选 |
|---|---|---|
| 文字母版 `layout` | `topleft` 左上大字 / `right` 右侧右对齐 / `center` 居中 / `bottom` 底部字幕带式（**字幕得放顶部**，先问用户） | 看图的留白习惯：主体多在右 → topleft；主体多在左 → right；氛围图多 → center |
| 强调色 `gold` + 正/负色 `teal` `coral` + 压暗色 `bg` | 从本期照片里取：夜景冷调 → 香槟金 `#D9C49C` + 冷蓝底 `#070B14`；暖光门店 → 陶土橙 `#E07B45` + 暖黑 `#0B0907`；白天/自然 → 墨绿、赭石… | 照片入库后看一眼主色，强调色要和照片里的光源色呼应 |
| 照片处理 `tint` / `letterbox` / `grain` | 统一罩色（冷蓝、暖褐、青灰）、2.35:1 黑边、胶片颗粒，任意组合或都不用 | 电影感 / 纪录感 / 干净杂志感，三选一 |
| 入场 `enter` | `blur` 柔切（默认）/ `cut` 硬切 / `slideL` 横推 / `zoom` 缩放 | 节奏快、短句多 → cut；舒缓 → blur |
| 图表语言 | 柱状 / 阶梯 / 表格 / 折线 / 对比卡 | 跟数据形态走，但别和上一期同一种 |

写进发布清单时，一句话说清这期"看起来像什么"，再附一行机器可读的注释（脚本会把它写进 photo.json 的 `style`）：

```markdown
- 本期视觉方案：冬夜橱窗的冷调，字像奢侈品广告——香槟金、冷蓝罩色、2.35:1 黑边、硬切。和第 6 期（暖黑 + 陶土橙 + 左上大字 + 柔切）换了配色、照片处理、入场 3 项。
<!-- STYLE_DNA layout=topleft gold=#D9C49C coral=#C9545A teal=#9DB9CF bg=#070B14 dim=#B9C0CC tint=#1B2A44 tintOpacity=0.3 enter=cut letterbox=1 grain=0 badge=0 scale=v2 -->
```

效果对比参考：`references/style-compare-ep7.jpg`（上：第 7 期实际版，下：同一内容换一套方案）。

**字号换成 v2 档位（2026-10 起的新期默认）**：`h` 88 / `t` 44 / `big` 180。旧期是 `h` 66 / `t` 38 / `big` 150，靠 `style.scale` 区分，photo.json 里写 `"scale": "v2"` 就切新档，不写还是旧档（已发布各期重渲不会变样）。

**字号放大有个硬约束：宽度。** h88 在 L 列（w=900）里**最多 12 字**，超了就换行、砸到下一行：

| 档位 | 放哪 | 字数上限 |
|---|---|---|
| `h` 140 金句 | 必须 `TW` 全宽 | 7–8 字 |
| `h` 112 大字 | `TW` 或卡内 | 9–10 字 |
| `h` 88 默认 | L 列 / 卡内 900 宽 | **12 字** |
| `h` 64 旧档 | 同上 | 16 字 |

叠字超字数不是靠缩字号解决，是**拆句**：一句变两句，或者把修饰语砍掉只留主谓宾。字号往回缩会让整期节奏垮掉。

**字体不随期换，但有分工**（对比图 `references/font-compare-2-2026-10-14.png`）：标题得意黑；所有数字自动走数黑体；定义卡的大词加 `"font": "song"` 走锦书宋，一期只用一两次；对白、人说的话加 `"quote": true` 走文楷加金色引号；小字思源黑。（文楷以前还管角标里那个"像素呼吸"，角标取消后就只管对白了。）写分场景表时，叠字里的对白用「“……”」或「老板：……」写出来，脚本会自动标成 quote。一期画面里最多同时出现这五种，不要再加别的字体。

然后是提示词和规格，固定写法（除非用户要换风格）：

```markdown
### 全局风格
- 风格：写实电影感摄影，夜景 / 室内暖光、浅景深、35mm；**画面里不要有任何文字**（招牌、数字、价签都不要，字由代码加）
- 一致性：先出 1 张主场景定调，之后所有同场景的图用它垫图；人物服装、关键道具（本期：___）在所有图里保持一致
- 规格：16:9，宽 ≥ 2560（即梦 2752×1536 直接可用），JPG/PNG，文件名带编号如 `S01.jpg`
- 提示词前缀（每张都拼在前面）：`写实摄影，电影感，<本期场景一句话>，<灯光>，浅景深，35mm 镜头，<人物设定>，画面无文字，16:9`
- 留白：每张图注明文字放哪一侧，那一侧构图留 35–45% 相对干净的区域（代码会压暗，不必纯色）
```

### 2. 分场景表格

列固定，脚本按列位解析：

```markdown
### 分场景

| # | 场景 id | 起始句 | 这段在讲什么 | 图 | 叠字 | 环境声 |
|---|---|---|---|---|---|---|
| 01 | shop | 0 | 晚七点排队，老板再叫一个人 | S01 | 「门口排了十几个人」「老板：再叫一个人 +1」「这下总该快了吧？」 | 奶茶店 |
| 05 | chapter | 10 | 第 1 章 章节卡 | — | — | — |
| 07 | bars | 13 | 1→5 人出杯 30/60/80/85/87?，柱状图 | S08 S02 | 柱状图（代码）「第四个人：只多了 5 杯」 | — |
```

- **场景 id**：小写英文，之后就是代码里的名字。章节标题行固定 `chapter`。
- **起始句**：口播稿行号，从 0 起，章节标题也占一号。写之前先跑 `python 工具/video-render/scripts/build_timeline.py <口播稿.md> epN --list` 看编号。第一行必须是 0。
- **切分粒度**：一个场景 = 一个画面主体，通常 4–12 行（口播稿一行最多 16 字宽，见 AGENTS.md）、10–30 秒；一段话里数字连续变化（柱状图、表格）可以放一个长场景。5 分钟的片子 20–25 个场景。
- **图**：可以写多张（第一张是底，第二张在场景中途淡入切换），可以复用别的场景的图。纯文字卡写 `—`。
- **叠字**：每条「」一句，按出现顺序挂到场景内的句子上；图表写「柱状图（代码）」这类说明。叠字不是字幕，是**提炼**：短、有数字、有对比。
- **环境声**：按 `工具/音效库/补充音效清单.md` 里的名字写（奶茶店 / 街道夜晚 / 森林 / 办公室 / 商场 / 厨房 / 雨 / 咖啡馆），只在开场、金句、结尾这类需要氛围的场景写。


### 卡片：实物感（2026-10-29 起新期默认）

新期 `style.cardSkin: "tactile"`：卡不再是半透明色块，是"一张能拿起来的牌"——厚底边、细金边、四角角花、±6px 漂动、从侧面飞入带轻回弹。四种语义不变，另加 `photo` 卡（上图下字，一个实体一张）。验证台：`python3 scripts/lab.py tactile` → `out/stylelab/tactile-sheet.jpg`。审阅稿见 `references/动效升级审阅稿-2026-10-29.md`。

**实物卡的图从哪来**：出图清单最后加一段「卡内小图」，编号 `C01`…，方形、主体居中、无文字；入库 `python3 scripts/import_cards.py <文件夹> <epN> --need <发布清单.md>`。

**数值怎么动**（替代"只有 CountUp"）：`odometer` 里程表（价格、年份）/ `flap` 翻牌（旧判断换新判断）/ `slam` 砸入（本期核心数，一期 1–2 次）/ `rank` 排名换位 / `units` 实物堆叠（人数、钱数）/ `fill` 液面（占比）/ `graph` 卡片连线（关系）。字段见 `references/photo-json.md`。

验收标准（Heer & Robertson 2007）：动画每一帧都是合法数据状态（柱子不先缩再长、里程表不绕圈经过无关数字）；复杂变化分阶段（先列头再填行）；慢进慢出可预判；同一数据项变化前后位置不变（rank 里同一行始终是同一个元素）。

### 卡片：四种长相，语义固定

卡不是装饰，是「这块信息是什么性质」的视觉标签。写分场景表时在叠字后面标出用哪种卡，photo.json 里走 box 的 `card` 字段（整组字自动套壳，里面的字自动切黑/白）。

| card | 长相 | 只用在 |
|---|---|---|
| `solid` | 金底黑字 + 硬投影 | **结论、揭晓**。一期最多出现 2 次，它太重了 |
| `paper` | 米白、微斜 1.6°、软阴影 | **原文、书、新闻标题、账单**。一期最多 1 次 |
| `notch` | 深底 + 左边一道强调色竖条 | **前提、定义、边界条件**（替掉旧的 `panel`） |
| `tab` | 深底 + 上面挂一个分类签 | **一条数据、一个例子**。数据场景的默认长相 |

`panel` 保留兼容，新期一律用 `notch`。

**卡宽走栅格**：主卡 900（对齐 L 列），数字卡 780。四张卡左边缘都在 `box.x` 上，右边缘因此也是齐的 —— 别再让每张卡自己定宽，那会看起来"不齐但说不出哪不对"。

**分类签的颜色只有两种**：
- 中性信息（时间、地域、数据来源）→ 不写颜色，默认 `dim` 黑底白字
- 判断、结论 → `gold`
- `teal` / `coral` **严格留给正负对比**（涨/跌、赚/亏），不参与装饰。同一个「数据」标签一会儿 teal 一会儿 coral，观众读到的是矛盾信号。

**因果链用 `stack`**：三张依次推入，最后一张金底高亮。表达"省煤 → 台数涨 → 总消耗涨"这种链式因果。主卡宽 820，错位 44，副标题超宽走省略号（不许换行撑出卡外盖住下一张 —— 这是 2026-10 修掉的 bug）。

### 字效：三个，都克制

写在 `h` 元素上，`textfx` 字段：

| 值 | 效果 | 用在哪 |
|---|---|---|
| `outline` | 空心描边 | 金句的"空心版"，必须和一行实心字搭配出对比 |
| `gradient` | 金→橙→红渐变 | **一期只给一处**，留给本期的核心概念词（"杰文斯悖论"） |
| `reveal` | 从左往右擦出 | 揭晓的动作：答案、反转、结论出现的那一刻 |

`stagger`（逐字入场，每字晚 3 帧、上浮 0.25×字号）**每期最多 2 次**：开场钩子 + 结尾金句。中间段用它，节奏会拖。

### 3. 出图清单

每张图只写一次：

```markdown
### 出图清单（共 N 张）

先出 **S01**，确认风格后用它垫图出其余。

| 编号 | 画面 | 文字放哪侧 | 用在 |
|---|---|---|---|
| S01 | 夜晚奶茶店外景，暖黄灯光，门口一条十几人的队伍，透过橱窗能看到吧台里 3 个店员，老板站在门边招手 | TW | 01, 23 |
| S02 | 队伍中段特写，年轻人侧脸看手机，主体靠右 | TL | 02, 09 |
```

画面描述要能直接当提示词主体：机位（外景 / 内景平视 / 俯视 / 特写 / 顾客视角）、谁在干什么、关键道具位置、情绪。镜像构图的一对图（分屏用）标 `S20A / S20B`，并写明主体各靠哪一侧。

**「文字放哪侧」写画面区域名**（3 列 × 3 行：`TL TC TR / ML MC MR / BL BC BR`，整行居中用 `TW MW BW`）。这一列同时是给用户出图时的留白提示和脚本填 `box` / `grad` 的依据——同一套词，出图、填 JSON、看拼图提意见都用它，不用再翻译"上 1/3"是多少像素。详见 `references/photo-json.md`「画面区域」。

写完跑一次校验（起始句、id、列出要出的图），并且**顺手把渲染工程搭起来、先用占位图渲一张拼图**——版式问题在用户出图之前就能发现：

```bash

cd 工具/video-render
```

## 渲染阶段：收到字幕和图之后

### 0. 收料检查

- srt：中文、一行一句、和剪映版一一对应。双语的也行（只取第一行）。
- 图：一个文件夹，文件名里有编号。
- 用户如果临场改了词：脚本能容忍少量改词、漏一两句（会打印出入），出入太多会停下 → 先把口播稿改成实际念的版本。

### 1. 建期 + 入库 + 时间轴

```bash
cd 工具/video-render
python3 scripts/new_episode.py ep7                                            # 写稿阶段没建的话：建 src/ep7/、public/ep7/photos/，注册 Ep7Photo / Ep7PhotoCheck / Ep7Sheet
python3 scripts/scenes_from_checklist.py "<发布清单.md>" "<口播稿.md>" ep7       # → scenemap.json、scene-names.json、photo.json 骨架（已有 photo.json 不覆盖）
python3 scripts/import_photos.py "<用户的图片文件夹>" ep7 --need "<发布清单.md>"  # 裁 16:9、统一命名 → public/ep7/photos/，报缺图；会覆盖同名占位图
python3 scripts/timeline_from_srt.py "<口播稿.md>" "<口播.srt>" ep7 src/ep7/scenemap.json   # → timeline.json（覆盖估算版）
```

缺图时先告诉用户缺哪几张；能用别的图顶就在 photo.json 里改 `photo`，别等。

### 2. 填 photo.json

骨架已经有场景、照片、叠字。逐个场景补：推拉方向、压暗侧、每条字的大小 / 颜色 / 出现句、强调标记、音效。字段说明和套路见 `references/photo-json.md`。原则：

- **场景不写 `box` / `grad` 就走本期 `style.layout` 的母版**；只在照片主体位置和母版冲突时单独给 `box`。别每个场景都手写 `box`，否则换母版就不生效了。
- 字压在照片相对干净的一侧（和出图清单里的留白一致），`grad` 设成同一侧。
- 一个场景内：第一句出小字（dim）铺垫，关键句出大字（白 / 金），数字单独做 `big` 或 `count`。
- 要划掉的旧判断用 `strikeAt`；两个对立项用 `compare` 或 `split`；盖章式关键词用 `stamp`。
- 柱状图、表格、折线这类按句子逐步出现的图表写进 `src/ep7/custom.tsx`，参考 `src/ep6/custom.tsx`；photo.json 里 `{"type":"custom","name":"xxx"}` 引用。
- 音效默认已经配好（字出现 pop、盖章 impact、数字 ding…），只在揭晓点手动加 `impact` / `error` / `cash`，别处不用管。

### 3. 看图 → 小样 → 全片

```bash
python3 scripts/render.py ep7 sheet        # 关键帧拼图，10 秒出一张 out/ep7-sheet.jpg，每个场景 1–4 格
python3 scripts/render.py ep7 check 40     # 前 40 秒带字幕的核对版 out/ep7-check.mp4
python3 scripts/render.py ep7 full         # 正式版（只有音效）out/ep7-photo.mp4，7 分钟片约 8 分钟
python3 scripts/render.py ep7 fullcheck    # 全片带字幕核对版（可选）
```

`full` / `fullcheck` 走分段渲染（`scripts/render_seq.py`）：2 个进程并行出图片序列 → 查花屏帧兜底 → 编码 → 合音频。
- 中途崩了、卡死了：**直接重跑同一条命令**，已出好的帧不重出；单段卡死会自动超时重试
- 改过 photo.json 或代码之后重出全片：加 `--fresh`（`python3 scripts/render.py ep7 full --fresh`），否则会沿用旧帧
- 只是画面要重出、音效没动：加 `--audio-from <旧成片.mp4>` 直接拷旧音轨，省掉单独渲音频的约 4 分钟
- 图片序列整期约 5 GB，渲完自动删；硬盘剩余不足会直接停
- 必须用 Remotion 自带的 chrome-headless-shell（`remotion.config.ts` 默认就是）。本机 Chrome 会随机出花屏帧（整帧缩成 3×3 平铺、叠字丢失），2026-10 的 ep8 第一版就带了 69 帧，见 `工具/video-render/docs/渲染方式测试-2026-10-28.md`
- 交付前可以再查一遍：`python3 scripts/glitch_check.py out/ep7-photo.mp4`，应为「坏帧 0」

顺序不要跳：拼图自己先按下面的检查单过一遍，改完再给用户看拼图；用户认可后出 40 秒小样；再全片。改字之后只重渲拼图，不要动不动渲全片。

**拼图检查单**（拼图上叠着区域网格和红色字幕禁区线，按"场景号 → 问题 → 用区域名写的修法"逐条列出来，改完再渲一次；人对一闪而过的遮挡也很敏感，宁可多挑）：

1. 遮脸 / 遮主体：字压在照片里的人脸、产品、手上 → 换 `box` 到另一个区域，或改 `origin` 把主体推开
2. 出界：字超出画面边缘、换行后撑出文字框 → 缩 `size` 或改 `w`
3. 进字幕区：任何字的底边越过 y=820 红线 → 挪上去；`center` 和 `bottom` 布局重点查最后一条
4. 该收没收：上一句的字还留在屏上，和下一句的字叠在同一区域 → 给前一条加 `until`
5. 空档：一个场景连续 8 秒以上没有任何字出现或变化 → 补一条小字，或拆场景
6. 同图同动：连续三个场景用同一张图、同一个推拉方向 → 换 `move` 或 `origin`
7. 对比度：字压在照片亮部看不清 → `grad` 设到字那一侧，或加 `dim`
8. 字体用对没：数字是不是数黑体（乱码或方块说明字体没加载）、定义卡大词是不是 `song`、对白有没有 `quote`

## 禁用清单

拼图审查和填 photo.json 时按这个否决，比"看着不太好"更稳：

- 禁止字进字幕区（y > 820）
- 禁止一个区域里前一条字没走、后一条就来（必须 `until`）
- 禁止一个场景 8 秒以上无字
- 禁止连续三个场景同图同推拉
- 禁止一期内出现第六种字体，禁止把标题换成得意黑以外的字体（定义卡大词和对白除外）
- 禁止一个场景内出现两处以上 `gold` 大字（强调色只给一处）
- 禁止照片里有文字（招牌、价签、数字）；有就让重出或用 `grad` 压掉
- 禁止手写像素坐标做 `box`（除非区域名真放不下）；像素框会盖掉母版，换 layout 不生效
- 禁止叠卡文字换行撑出卡外（撑出去就盖住下一张；超宽走省略号，或者把副标题砍短）
- 禁止 `teal` / `coral` 当装饰色（分类签、卡片边、标签底都不行，它们只表示正负）
- 禁止一期里 `gradient` 出现两次以上、`stagger` 出现三次以上
- 禁止 `slam` 一期超过 2 次；禁止同一场景里 `odometer` / `flap` / `slam` 同时出现两种以上（数值动效一场一种）
- 禁止 `photocard` 用真 logo / 国旗（版权），用字卡
- 禁止一期内混用 `cardSkin`：要么全实物、要么全扁平

## 常见问题

- **字和字幕打架**：字幕在底部 70px 处，画面文字别放到 y > 820。`center` 布局的场景检查最后一条字的位置。
- **照片切换太频繁**：一个场景一张底图 + 最多一次 `swap`；连续三个场景用同一张图时换推拉方向（in / out）和 origin，别一模一样。
- **用户出的图有文字**：让重出无文字版，或者在 photo.json 里把 `origin` 推到避开文字的区域、用 `grad` 压掉。
- **图不够**：同一张图可以用 `blur` + `dim` 做虚化底（定义卡、章节卡、结尾都这么干），不用每段都要新图。
- **字体**：五款都打包在 `assets/fonts/`（得意黑 / 数黑体 / 锦书宋 / 文楷 / 思源黑），分工见「全局风格」一节，**不随期换**。`style.titleFont` 这个开关留着，只在用户明确要求时用。渲出来数字是方块 → woff2 没加载，看 `kit.tsx` 的 `useFonts`。
- **两期长得太像**：检查发布清单有没有写 STYLE_DNA、photo.json 的 `style` 有没有生效、场景是不是都手写了 `box` 把母版盖掉了。
- **音效单调 / 缺环境声**：让用户按 `工具/音效库/补充音效清单.md` 补，补完 `python scripts/import_sfx.py`。
- **Windows / Mac**：路径和 Python 命令的区别见开头那张表——Mac 用 `python3`，Windows 用 `python`；两边都用 Remotion 自带的 chrome-headless-shell 渲染（新机器先跑一次 `npx remotion browser ensure` 下载；实在下载不了才设 `USE_SYSTEM_CHROME=1` 退回本机 Chrome，那样会有花屏，交付前必须跑 `glitch_check.py`）。Mac 上没有真图时先 `placeholder_photos.py` 出占位图再渲拼图。
