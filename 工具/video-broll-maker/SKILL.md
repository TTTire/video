# 像素呼吸 B-roll 动画轨

渲染工程在 `工具/video-render/`（Remotion，命令都在这个目录下运行）。工作区根目录：

| 系统 | 工作区根目录 | Python 命令 |
|---|---|---|
| macOS | `/Users/tttire/Documents/工程队/视频选题` | `python3` |
| Windows | `E:\视频脚本` | `python` |

下文命令一律用相对路径（`cd 工具/video-render`），两套系统都能直接跑；只有 Python 命令按上表区分。

成片是什么：1920×1080 / 30fps、和用户口播等长、**只有音效没有配音**的动画轨。字幕和 BGM 用户在剪映加，所以画面文字压在上 2/3，底部留字幕位。

出镜怎么合：两条路，用户选——
1. **用户自己叠**：拿 B-roll 动画轨和 A-roll 在剪映里从 0 秒对齐，想露脸的地方切掉动画轨（第 8 期及以前都这么干）
2. **引擎合**（2026-10-29 起）：用户给粗剪 A-roll（和 srt 同一条时间线），photo.json 写 `aroll.cues`（要点 id → full / half / bubble），引擎渲出 B-roll + 出镜层的成片，小圆 ⇄ 全屏之间是圆形 iris 切换。A-roll **静音**，人声和字幕仍由用户在剪映加。字段见 `references/photo-json.md`「出镜层」

## 写稿阶段：画面与素材清单

写在发布清单 `## 画面与素材清单` 下，三部分：全局风格、分场景表格、出图清单（最后一段是卡内小图）。**格式和每一列怎么填见 [references/checklist-format.md](references/checklist-format.md)，写之前先读完**；叠字按下一节「画面规则」写。

最容易写错的几处：
- `STYLE_DNA` 写全：新期一律带 `badge=0 scale=v2 textEnter=fade cardSkin=tactile`。脚本按它**整体重写** photo.json 的 `style`，漏写 `textEnter` / `cardSkin` 就退回扁平卡 + 飞入。
- 分场景表第 3 列填讲稿卡的要点 id：第一行 `0.1`，三张章节卡 `1.0` / `2.0` / `3.0` 都要有。
- 「文字放哪侧」一张图只写一个区域名。
- 环境声只写音效库里已经有的（现在只有「商场」「街道夜晚」）；要别的，在出图清单后面加补音效任务。

写完跑一次校验（起始要点、id、列出要出的图），并且**顺手把渲染工程搭起来、先用占位图渲一张拼图**——版式问题在用户出图之前就能发现：

```bash
# 从工作区根目录进来；Windows 把所有 python3 换成 python
ruby 工具/validate_package.rb "进行中/<选题文件夹>"
cd 工具/video-render
python3 scripts/new_episode.py epN        # AI经济学期用 ai01、ai02
python3 scripts/scenes_from_checklist.py "<发布清单.md>" "<讲稿卡.md>" epN --force   # → scenemap / scene-names / photo.json 骨架，打印每个场景的要点范围
python3 scripts/make_timeline.py "<讲稿卡.md>" epN [--cpm 200]                # 录前：按要点字数估时的预览时间轴（录完用 --starts 覆盖）
python3 scripts/placeholder_photos.py epN                                     # 没到的图先用占位图
# 把 photo.json 从骨架填成正式版（见渲染阶段第 2 步），然后：
python3 scripts/render.py epN sheet
```

`scenes_from_checklist.py` 的 `--force` 只在这第一次加：`new_episode.py` 建的 photo.json 是空的占位，不加 `--force` 不会写场景骨架（只更新 style）。之后再加，会把手调过的 photo.json 整个重写成骨架。

这一步做完，渲染阶段只剩"换真图 + 换真时间轴 + 微调"。

## 画面规则（写叠字、填 photo.json、看拼图都按这个）

### 字号和字数

**字号换成 v2 档位（2026-10 起的新期默认）**：`h` 88 / `t` 44 / `big` 180。旧期是 `h` 66 / `t` 38 / `big` 150，靠 `style.scale` 区分，photo.json 里写 `"scale": "v2"` 就切新档，不写还是旧档（已发布各期重渲不会变样）。

**字号放大有个硬约束：宽度。** h88 在 L 列（w=900）里**最多 12 字**，超了就换行、砸到下一行：

| 档位 | 放哪 | 字数上限 |
|---|---|---|
| `h` 140 金句 | 必须 `TW` 全宽 | 7–8 字 |
| `h` 112 大字 | `TW` 或卡内 | 9–10 字 |
| `h` 88 默认 | L 列 / 卡内 900 宽 | **12 字** |
| `h` 64 旧档 | 同上 | 16 字 |

叠字超字数不是靠缩字号解决，是**拆句**：一句变两句，或者把修饰语砍掉只留主谓宾。字号往回缩会让整期节奏垮掉。

### 字体

**字体不随期换，但有分工**（对比图 `references/font-compare-2-2026-10-14.png`）：标题得意黑；所有数字自动走数黑体；定义卡的大词加 `"font": "song"` 走锦书宋，一期只用一两次；对白、人说的话加 `"quote": true` 走文楷加金色引号；小字思源黑。（文楷以前还管角标里那个"像素呼吸"，角标取消后就只管对白了。）写分场景表时，叠字里的对白用「“……”」或「老板：……」写出来，脚本会自动标成 quote。一期画面里最多同时出现这五种，不要再加别的字体。每种元素具体走哪个字体见 `references/photo-json.md`「字体」。

### 卡片：实物感（2026-10-29 起新期默认）

新期 `style.cardSkin: "tactile"`：卡不再是半透明色块，是"一张能拿起来的牌"——厚底边、细金边、四角角花、±6px 漂动、从侧面飞入带轻回弹。四种语义不变，另加 `photo` 卡（上图下字，一个实体一张）。验证台：`python3 scripts/lab.py tactile` → `out/stylelab/tactile-sheet.jpg`。审阅稿见 `references/动效升级审阅稿-2026-10-29.md`。

**实物卡的图从哪来**：出图清单最后加一段「卡内小图」，编号 `C01`…，方形、主体居中、无文字；入库 `python3 scripts/import_cards.py <文件夹> <epN> --need <发布清单.md>`。

**数值怎么动**（替代"只有 CountUp"）：`odometer` 里程表（价格、年份）/ `flap` 翻牌（旧判断换新判断）/ `slam` 砸入（本期核心数，一期 1–2 次）/ `rank` 排名换位 / `units` 实物堆叠（人数、钱数）/ `fill` 液面（占比）/ `graph` 卡片连线（关系）。字段见 `references/photo-json.md`。

验收标准（Heer & Robertson 2007）：动画每一帧都是合法数据状态（柱子不先缩再长、里程表不绕圈经过无关数字）；复杂变化分阶段（先列头再填行）；慢进慢出可预判；同一数据项变化前后位置不变（rank 里同一行始终是同一个元素）。

### 卡片：四种长相，语义固定

卡不是装饰，是「这块信息是什么性质」的视觉标签。写分场景表时在叠字后面标出用哪种卡，photo.json 里走 box 的 `card` 字段（整组字自动套壳，里面的字自动切黑/白）。

| card | 长相 | 只用在 |
|---|---|---|
| `solid` | 金底黑字 + 硬投影 | **结论、揭晓**。一期最多出现 2 次，它太重了 |
| `paper` | 米白、微斜 1.6°、软阴影 | **原文、书、新闻标题、账单**。一期最多 1 次 |
| `notch` | 深底 + 左边一道强调色竖条 | **前提、定义、边界条件**（替掉旧的 `panel`） |
| `tab` | 深底 + 上面挂一个分类签 | **一条数据、一个例子**。数据场景的默认长相 |

`panel` 保留兼容，新期一律用 `notch`。

**卡宽走栅格**：卡宽默认一律 900，对齐 L 列。数字卡也是 900，以前文档写的 780 从没生效过。这样几张卡的左边缘都在 `box.x` 上，右边缘也是齐的 —— 别让每张卡自己定宽，那会看起来"不齐但说不出哪不对"。真要窄一张，就写 `cardW`。

**分类签的颜色只有两种**：
- 中性信息（时间、地域、数据来源）→ 不写颜色，默认 `dim` 黑底白字
- 判断、结论 → `gold`
- `teal` / `coral` **严格留给正负对比**（涨/跌、赚/亏），不参与装饰。同一个「数据」标签一会儿 teal 一会儿 coral，观众读到的是矛盾信号。

**因果链用 `stack`**：三张依次推入，最后一张金底高亮。表达"省煤 → 台数涨 → 总消耗涨"这种链式因果。主卡宽 820，错位 44，副标题超宽走省略号（不许换行撑出卡外盖住下一张 —— 这是 2026-10 修掉的 bug）。

### 字效：三个，都克制

写在 `h` 元素上，`textfx` 字段：

| 值 | 效果 | 用在哪 |
|---|---|---|
| `outline` | 空心描边 | 金句的"空心版"，必须和一行实心字搭配出对比 |
| `gradient` | 金→橙→红渐变 | **一期只给一处**，留给本期的核心概念词（"杰文斯悖论"） |
| `reveal` | 从左往右擦出 | 揭晓的动作：答案、反转、结论出现的那一刻 |

`stagger`（逐字入场，每字晚 3 帧、上浮 0.25×字号）**每期最多 2 次**：开场钩子 + 结尾金句。中间段用它，节奏会拖。

## 渲染阶段：收到粗剪和图之后

### 0. 收料检查

- 粗剪：`工具/aroll-prep` 出的粗剪 mp4 + srt + words.json（分段录的先拼成一条）。字幕从录音来，不从讲稿卡导；srt 用 aroll-prep 的或剪映识别的都行。
- 图：一个文件夹，文件名里有编号（S01…，卡内小图 C01…）。收到后放进选题文件夹的 `图片素材/`（进 git，换机器时从这里重新入库）。
- 环境声：photo.json 里写的 `ambience` 都要在 `src/sfx-manifest.json` 的 ambience 里有（现在只有「商场」「街道夜晚」）。没有的，先让用户按 `工具/音效库/补充音效清单.md` 补，或者改成现有的。写了库里没有的名字不报错，引擎会在现有几条里按位置挑一条，声音和画面对不上。
- 要点起点表 `src/<ep>/starts.json`（录完后手填）：对照粗剪 srt / words.json，记下每条要点开口的时间——`{"0.1": "00:00.0", "0.2": "00:07.4", …, "1.0": "01:00.2", …, "end": "08:19.5"}`。
  - 讲稿卡里每个 id 都要有（含 `N.0`）；值写秒数或 `mm:ss.s`，在 0 和 `end` 之间，按讲稿卡顺序不往回走。时间以和 A-roll 同一条时间线的粗剪为准。
  - `N.0` = 上一章最后一句说完；`end` = 最后一句说完（给了 `--srt` 可省；`--srt` 只能和 `--starts` 一起用）。
  - **录的时候没讲的要点**，填和下一条**完全一样**的时间。它要是某个场景的起始要点，那个场景时长为 0、整个跳过（make_timeline 会列出来）。在场景中间的不会提示：挂在它上面的字会和下一条的字同一刻出来，要在 photo.json 里删掉或改挂。两种都自己记下来，交付时回写（见「4. 交付」）。别填成只差零点几秒——那个场景会闪几帧，还带一声 pop。
  - 脚本只查缺 id、多 id、往回走、end 太早；格式和范围不查（负数、多一段冒号都能过），填完自己扫一遍。

过关判据见「流程和关卡」的收料一行。

### 1. 建期 + 入库 + 时间轴

```bash
cd 工具/video-render
python3 scripts/new_episode.py ep7                                            # 写稿阶段没建的话：建 src/ep7/、public/ep7/photos/，注册 Ep7Photo / Ep7PhotoCheck / Ep7Sheet
python3 scripts/scenes_from_checklist.py "<发布清单.md>" "<讲稿卡.md>" ep7       # → scenemap.json、scene-names.json；photo.json 已存在时只按 STYLE_DNA 重写 style（还没有场景骨架就加 --force）
python3 scripts/import_photos.py "<选题文件夹>/图片素材" ep7 --need "<发布清单.md>"  # 裁 16:9、统一命名 → public/ep7/photos/，报缺图；会覆盖同名占位图
python3 scripts/import_cards.py "<选题文件夹>/图片素材" ep7 --need "<发布清单.md>"   # 有卡内小图时：1:1 裁切 → public/ep7/cards/
python3 scripts/make_timeline.py "<讲稿卡.md>" ep7 --starts src/ep7/starts.json --srt "<粗剪.srt>"   # → timeline.json（source=starts，覆盖估算版）
```

- 缺图时先告诉用户缺哪几张；能用别的图顶就在 photo.json 里改 `photo`，别等。
- `import_photos` 的「还缺」**分不出占位图**：public 里有同名占位图就当成已入库，不会报缺。换上真图后看一眼拼图，还有占位图（深色渐变 + 圆里一个大编号 + 左下「占位图 Sxx」）就不能往下走。
- `import_photos` 只在宽度不到 1920 时警告；出图规格是宽 ≥ 2560，看它打印的原始尺寸，不够的让用户重出。

### 2. 填 photo.json

骨架已经有场景、照片、叠字。逐个场景补：推拉方向、压暗侧、每条字的大小 / 颜色 / 出现在第几条要点、强调标记、音效。字段说明和套路见 `references/photo-json.md`。原则：

- **场景不写 `box` / `grad` 就走本期 `style.layout` 的母版**；只在照片主体位置和母版冲突时单独给 `box`。别每个场景都手写 `box`，否则换母版就不生效了。
- 字压在照片相对干净的一侧（和出图清单里的留白一致），`grad` 设成同一侧。
- 一个场景内：第一条要点出小字（dim）铺垫，关键要点出大字（白 / 金），数字单独做 `big` 或 `count`。
- 要划掉的旧判断用 `strikeAt`；两个对立项用 `compare` 或 `split`；盖章式关键词用 `stamp`。
- 柱状图、表格、折线这类按要点逐步出现的图表写进 `src/ep7/custom.tsx`，参考 `src/ep9/custom.tsx`（按逐字时间对口播）或 `src/ep6/custom.tsx`（按要点逐步出）；photo.json 里 `{"type":"custom","name":"xxx"}` 引用。
- 音效走精简（`style.sfx: "sparse"`，2026-11 起新期默认，骨架自动写上）：字（h / t / tag）和 photo 卡出现不响，只有"变化"响——换场景 pop、章节卡 flip、盖章、砸入、翻牌、里程表、数字 ding、划掉、换图 whoosh、出镜层切换 whoosh（正好落在换场景那一帧的不再叠一声）。AI03 前 90 秒实测：26 声 → 10 声。揭晓点（答案、反转、结论出现那一刻）手动加 `impact` / `error` / `cash`；别给普通字加 `sfx`，那等于把精简关掉。已发布各期不写 `sfx`，重渲照旧每条字一声 pop。

**骨架里要手改的 `grad`**（脚本按出图清单的「文字放哪侧」填，有两处填得不对）：
- `BW` 的图填成了 `top`，方向反了，改成 `bottom`；`BL` / `BC` / `BR` 按列填成 left / all / right，字压在底部时多半该用 `bottom`，看拼图定。
- 出图清单没写区域的图，骨架照样写了 `"grad": "left"`，会盖掉本期母版。母版不是 `topleft` 的期，把这条删掉。

**引擎现在的行为，写的时候绕开**（已发布的期依赖这些行为，所以没改）：
- `center: true` 时场景的 `box` 不生效，字固定从 y 110 起（居中框 x 90、宽 1740），压暗默认 `none`。要居中又要调高低，别写 `center`，写 `box`（如 `"MW"`，或像素框加 `"align": "center"`）并自己写 `grad`。
- 栏目卡（`type: "series"`）看场景里有几条要点：1 条（讲稿卡期都是这样）→ 1.5 秒滚序号 + 标题、再过 1.5 秒出 tagline；3 条及以上 → 序号跟第 2 条、tagline 跟第 3 条；**正好 2 条 → tagline 永远不出**（ep7 就是这样）。栏目卡场景别跨 2 条要点。
- 有出镜层的期：photo.json 没写 `"faceTrack": false`，就要有脸轨（`src/<ep>/aroll-face.json`，并且 `src/photo/faces.ts` 里有这一期）。缺了引擎不报错，直接用 `face`（没写就是 [0.5, 0.42]），小圆里的脸会偏。所以出镜层的合成一律用 `render.py` / `render_seq.py` 渲（它们会先确认脸轨），别直接 `npx remotion render`。

### 3. 看图 → 小样 → 全片

```bash
python3 scripts/render.py ep7 sheet        # 关键帧拼图，10 秒出一张 out/ep7-sheet.jpg，每个场景 1–4 格
python3 scripts/render.py ep7 check 40     # 前 40 秒带字幕的核对版 out/ep7-check.mp4
python3 scripts/render.py ep7 full         # 正式版（只有音效）out/ep7-photo.mp4，7 分钟片约 8 分钟
python3 scripts/render.py ep7 fullcheck    # 全片带字幕核对版（可选）
```

`full` / `fullcheck` 走分段渲染（`scripts/render_seq.py`）：默认 2 个进程 × 并发 2 出图片序列 → 查花屏帧兜底 → 编码 → 合音频。
- 中途崩了、卡死了：**直接重跑同一条命令**，已出好的帧不重出；单段卡死会自动超时重试
- **脚本只按帧号判断帧在不在，不看内容。** 改过 photo.json、custom.tsx、引擎代码，换过图（包括占位图换真图），重跑过 make_timeline 之后重出全片，都要加 `--fresh`（`python3 scripts/render.py ep7 full --fresh`），否则会沿用旧帧，新旧画面混在一起
- 只是画面要重出、音效没动：加 `--audio-from <旧成片.mp4>` 直接拷旧音轨，省掉单独渲音频的约 4 分钟
- 图片序列整期约 5 GB，渲完自动删；硬盘剩余不足会直接停
- 渲完看最后几行：出现「⚠️ 输出帧数 X，应为 Y」就是成片缺帧——脚本不会报错退出，帧目录照样删掉。这个文件不能交付，加 `--keep` 重渲查原因
- 必须用 Remotion 自带的 chrome-headless-shell（`remotion.config.ts` 默认就是）。本机 Chrome 会随机出花屏帧（整帧缩成 3×3 平铺、叠字丢失），2026-10 的 ep8 第一版就带了 69 帧，见 `工具/video-render/docs/渲染方式测试-2026-10-28.md`。`--no-check` 只在用 headless shell 时加
- 交付前可以再查一遍：`python3 scripts/glitch_check.py out/ep7-photo.mp4`，应为「坏帧 0」

顺序不要跳：拼图自己先按下面的检查单过一遍，改完再给用户看拼图；用户认可后出 40 秒小样；再全片。改字之后只重渲拼图，不要动不动渲全片。

**拼图检查单**（拼图上叠着区域网格和红色字幕禁区线，按"场景号 → 问题 → 用区域名写的修法"逐条列出来，改完再渲一次；人对一闪而过的遮挡也很敏感，宁可多挑）：

1. 遮脸 / 遮主体：字压在照片里的人脸、产品、手上 → 换 `box` 到另一个区域，或改 `origin` 把主体推开
2. 出界：字超出画面边缘、换行后撑出文字框 → 缩 `size` 或改 `w`
3. 进字幕区：任何字的底边越过 y=820 红线 → 挪上去；`center` 和 `bottom` 布局重点查最后一条
4. 该收没收：上一条要点的字还留在屏上，和下一条要点的字叠在同一区域 → 给前一条加 `until`
5. 空档：一个场景连续 8 秒以上没有任何字出现或变化 → 补一条小字，或拆场景（视觉语言 v2 要改这条，见「禁用清单」末尾）
6. 同图同动：连续三个场景用同一张图、同一个推拉方向 → 换 `move` 或 `origin`
7. 对比度：字压在照片亮部看不清 → `grad` 设到字那一侧，或加 `dim`
8. 字体用对没：数字是不是数黑体（乱码或方块说明字体没加载）、定义卡大词是不是 `song`、对白有没有 `quote`

### 3b. 出镜层（可选）

用户给了 A-roll（必须是和 srt 同一时间线的粗剪、从 0 秒对齐、30fps；分辨率 16:9 即可，4K 也行）：

```bash
# 一律转成 1080p 静音代理再放进工程（4K 解码拖慢渲染；成片 1080p，出镜层最大不超过原尺寸，代理不损画质）
# 用户原片不动，剪映里照用原片的声音
ffmpeg -i "<A-roll.mp4>" -vf scale=1920:1080 -r 30 -an -c:v libx264 -crf 18 -preset fast public/epN/aroll.mp4
# 核对：代理时长和 srt 最后一条结束时间差不超过 1 秒，否则先问用户是不是换过剪辑
# photo.json 顶层写 aroll（src / idle / cues，face 不用写），cues 的 at 是要点 id：["0.1", "0.4"] = [起, 止)，止写 "end" 到片尾（老期写的是口播稿行号，照旧认）
python3 scripts/aroll_face.py epN            # 跟脸：逐帧找脸 → src/epN/aroll-face.json，看报告（约 1 分钟；忘了跑，渲出镜层时也会自动跑）
python3 scripts/aroll_cues.py epN            # 看每段模式 / 时间，核对节奏
python3 scripts/render.py epN arollsheet     # 拼图：小圆有没有压到字
python3 scripts/render.py epN arollclip 3070 3250   # 单看一处切换
python3 scripts/render.py epN aroll          # 成片 out/epN-full.mp4
```

**跟脸：小圆 / 半屏卡里人始终在中间**（2026-11-08 起）。分几条录、中间挪过位置，粗剪里人在画面的位置会跳（AI04：6 处跳剪换了位置，脸的横向位置在画面宽的 0.43–0.54 之间，固定一个 `face` 时 260 圆里最多偏 70 px）。`aroll_face.py` 用 OpenCV 的 YuNet 逐帧找脸：跳剪换位的那一帧取景跟着硬切（画面本来就在跳，看不出来）；同一条里人慢慢挪出 ±36 px 才用 1 秒慢进慢出平移补位，说话时的晃动不跟。AI04 实测跟脸后最多偏 15 px。
- 报告列出每一段取景（跳剪 / 平移）；带 ⚠ 的段是人太靠画面边、圆盖不满，对不到中间——告诉用户下次录的时候往中间坐
- `render.py` 的 arollcheck / arollsheet / arollclip 和 `render_seq.py` 渲 `EpNFull*` 之前都会检查：没有脸轨，或者代理换过（文件大小和脸轨记的不一样），就先跑一遍；`render_seq.py` 这时自动从头渲（之前的帧是旧取景）
- 全屏（full）态是 A-roll 原画面，不裁也不挪；人在全屏里偏了，只能录的时候摆正
- 老期（ep8 / ai03 / ai04）的 aroll 写了 `"faceTrack": false`，重渲照旧用固定 `face`，不变样
- 依赖 `pip install opencv-python-headless`（Mac 用 `pip3`），模型在 `assets/models/`

cue 怎么写：开场第一条要点 `full`；"我猜 / 我的感受 / 我打算"这类第一人称判断 `full` 或 `half`；数据、历史、图表段留 `bubble`（默认）；章节卡自动 `hide`。每段 bubble 超过 60 秒就插一段 full。`half` 卡位置固定在画面左边（x 60–700、y 90–810），只配 `right` 母版（字在右）；`topleft` / `center` 母版的期（比如 AI04）用它会盖住左列的字，第一人称段改用 `full` 或放大的小圆。

小圆大小分情况定，写在场景上：`"arollSize": "m"`（1.3 倍）/ `"l"`（1.6 倍），不写是默认 260。圆贴着默认落点的外角往画面里长，多占的是字列和照片那一侧（各档占哪块见 `references/photo-json.md`「出镜层」）：
- 放大：字只在小圆对面那一列——`topleft` 母版小圆在右上，字只用 L 列；`right` 母版小圆在左下，字只用 R 列、左下角没字。照片在小圆那一角是空景（天空、墙面、虚化），讲的是第一人称判断、自己的经历，又不值得切 full / half
- 保持默认：数据卡、stack、两张以上的卡、图表；字是整行宽（TW / MW）或落在小圆同一侧；照片主体就在那一角
- 相邻场景换大小是平滑缩放、不响；别每场都换，一段 bubble 里大小来回跳比一直小更乱
- 写完出 `arollsheet`，按拼图检查单第 1 条看小圆有没有压到字和脸。拼图每个场景只抽 1–4 帧，后出现的字容易漏看；交付前把成片按 2 秒一帧抽一遍

**交付文件和命名**（`<选题名>` = 讲稿卡文件名去掉 `-讲稿卡.md`）：

| 本期 | 交付文件（放进选题文件夹） | 怎么出 |
|---|---|---|
| 引擎合了出镜层 | `<选题名>-动画轨+出镜-仅音效-全片.mp4`（为主）；要分章再加 `<选题名>-动画轨+出镜-仅音效-0开头.mp4` / `-1第1章.mp4` / `-2第2章.mp4` / `-3第3章.mp4` | 整片渲一次 + `split_chapters.py` |

| 每期都有 | `<选题名>-剪辑说明.md`、`<选题名>-双语字幕.srt` | 见下 |

**有出镜层：整条成片为主，按章 4 段为辅**（2026-10-30 起）。整片只渲一次，加 `--keep` 留下图片序列和 wav，4 段用 `split_chapters.py` 从同一套帧 + 同一条 wav 切出来：

```bash
python3 scripts/render_seq.py epN --comp EpNFull --frames 0-<total-1> --out out/epN-full.mp4 --workers 3 --concurrency 3 --fresh --keep --no-check
python3 scripts/glitch_check.py out/epN-full.mp4                                   # 坏帧 0
cp out/epN-full.mp4 "<选题文件夹>/<选题名>-动画轨+出镜-仅音效-全片.mp4"
python3 scripts/split_chapters.py epN out/epN-full.mp4 "<选题文件夹>/<选题名>-动画轨+出镜-仅音效" --verify   # → -0开头 / -1第1章 / -2第2章 / -3第3章
rm -rf out/epN-seq
```

- `--workers 3 --concurrency 3` 稍快，但内存近 5 GB；内存紧就去掉这两项，用默认 2×2（最稳）。`--no-check` 只在用 headless shell（默认）时加。
- 切点 = 每张章节卡的起始帧（那一刻出镜层是 hide，两边没有进行中的转场），脚本从 timeline.json 自己取。`--verify` 把 4 段 concat 回去和整片比：接缝 ±3 帧 SSIM 应 ≥ 0.98，各段音频首尾和整片 wav 的偏差应 < 10%。
- 为什么不再各渲各段（ep8 实测）：每段单独渲、单独编 AAC，音轨比画面多 12–19 ms 末尾补零 + 21 ms 编码延迟，剪辑软件按音频长度首尾相接时每个接缝约 40 ms 声画错位或一声咔；画面本身逐帧一致，没问题。用户主用整条。
- **只重渲某一章**：`render_seq.py` 加 `--frames <该章帧区间> --out <另一个文件名> --fresh`。不写 `--out`，会把 `out/<ep>-photo.mp4` 覆盖成只有这一段；`--fresh` 会清掉这个合成之前留下的全部帧。这样渲出的段是独立音轨，替换完要听接缝；稳妥是整片重渲。

**只有动画轨**：把 `out/ep7-photo.mp4` 复制到选题文件夹（命名见上表）；需要分场景片段时：

```bash
python3 scripts/split_scenes.py out/ep7-photo.mp4 ep7 "<选题文件夹>/剪辑素材-分场景-仅音效" src/ep7/scene-names.json
```

## 讲稿卡增删要点之后

要点 id 是「章.序」：在一章里增、删、拆一条，后面的 id 全变；对不上就是画面错位（字出在别人的话上）。已经建了渲染工程的期，按顺序改：

1. 发布清单分场景表的起始要点 → 重跑 `scenes_from_checklist.py`（不加 `--force`：重写 scenemap / scene-names 和 style，不动场景；场景表里新增的场景要自己在 photo.json 里补）
2. `starts.json`：`make_timeline.py` 会报多出来 / 没填的 id，按新卡改
3. photo.json 里「场景内第几条要点」的下标：`at` `until` `swap.at` `strikeAt` `orderAt` `split.at`、`photorow` 每张卡的 `at`、`graph` 节点和边的 `at`。在场景中间增删一条，它后面的下标都要 ±1
4. `aroll.cues` 里的要点 id
5. `custom.tsx` 里写死的 `at(p, N)`、`p.step >= N`：脚本管不到，逐个对
6. 改完重渲拼图，和改之前的拼图逐场比：没动的场景应该一模一样

录完以后才发现卡和成片对不上的，按「4. 交付」的录后回写做，不删要点行。

## 改引擎或渲染脚本之前

改 `src/` 下各期共用的代码、会写渲染输入的脚本，或者升级 Remotion / 浏览器之前，先按 [references/golden-baseline.md](references/golden-baseline.md) 渲基线，改完逐帧对比。已发布的期，重渲必须和改前一模一样；预期之外的差异一律算 bug。只改某一期的 photo.json / custom.tsx、只改文档，都不用做。

## 禁用清单

拼图审查和填 photo.json 时按这个否决，比"看着不太好"更稳：

- 禁止字进字幕区（y > 820）
- 禁止一个区域里前一条字没走、后一条就来（必须 `until`）
- 禁止一个场景 8 秒以上无字（视觉语言 v2 要改这条，见本节末尾）
- 禁止连续三个场景同图同推拉
- 禁止一期内出现第六种字体，禁止把标题换成得意黑以外的字体（定义卡大词和对白除外）
- 禁止一个场景内出现两处以上 `gold` 大字（强调色只给一处）
- 禁止照片里有文字（招牌、价签、数字）；有就让重出或用 `grad` 压掉
- 禁止手写像素坐标做 `box`（除非区域名真放不下）；像素框会盖掉母版，换 layout 不生效
- 禁止叠卡文字换行撑出卡外（撑出去就盖住下一张；超宽走省略号，或者把副标题砍短）
- 禁止 `teal` / `coral` 当装饰色（分类签、卡片边、标签底都不行，它们只表示正负）
- 禁止一期里 `gradient` 出现两次以上、`stagger` 出现三次以上
- 禁止一期里 `solid` 卡超过 2 次、`paper` 卡超过 1 次
- 禁止 `slam` 一期超过 2 次；禁止同一场景里 `odometer` / `flap` / `slam` 同时出现两种以上（数值动效一场一种）
- 禁止 `photocard` 用真 logo / 国旗（版权），用字卡
- 禁止一期内混用 `cardSkin`：要么全实物、要么全扁平
- 禁止出镜小圆放右下角（`arollPos` 的 y > 600 且 x > 1500）：抖音右侧图标列和「全屏观看」按钮压在那里；右侧只能右上（默认），依据见 `references/douyin-safe-zone.md`

**视觉语言 v2 要改的写稿规则（还没生效）**：`工具/视觉语言v2-文字减量与展示形式方案-2026-11-13.md` 的第 0 批先在 10/100 消费者剩余（ep10）上试点，过了方案 §6 的判据再落地；落地时本文件和 `references/checklist-format.md` 要一起改下面这几条：
- 「8 秒无字」（本节、拼图检查单第 5 条）→ 「8 秒无变化」：出字、收字、换图、图表或数值动效、出镜切换都算变化，照片缓推不算。另加正向要求：每章留 1–2 处呼吸段（无字 + 底图缓推 + 出镜，每处 3–5 秒）。这两条用户 2026-11-13 都已确认。
- 叠字按类型配：证据、数字、结论才上字，讲述性的要点不上字；开场钩子那一句保留。
- 分场景表的叠字列可以写展示形式名，写法 `[document#3]` `[tagwall]` `[pyramid]` `[徽章:Kimi]`；引擎里有了对应元素才能写，现在脚本会把它当成一条字生成进骨架。
- 证据场景挂短标签（机构 / 资料名 / 年份），和事实核对的条目号对应；拿不到干净原图的证据用 `paper` 卡 + 短标签。
- 同屏文字元素 ≤ 4，怎么数见 v2 方案 §4。

ep10 的渲染阶段（用户录完以后）按方案 §6 的做法用这几条；其他期落地前仍按本文件执行。3–5 秒的呼吸段本来就不违反 8 秒的规定，哪一期都可以先留。

## 常见问题

- **字和字幕打架**：字幕在底部 70px 处，画面文字别放到 y > 820。`center` 布局的场景检查最后一条字的位置。
- **照片切换太频繁**：一个场景一张底图 + 最多一次 `swap`；连续三个场景用同一张图时换推拉方向（in / out）和 origin，别一模一样。
- **用户出的图有文字**：让重出无文字版，或者在 photo.json 里把 `origin` 推到避开文字的区域、用 `grad` 压掉。
- **图不够**：同一张图可以用 `blur` + `dim` 做虚化底（定义卡、章节卡、结尾都这么干），不用每段都要新图。
- **字体**：五款都打包在 `assets/fonts/`（得意黑 / 数黑体 / 锦书宋 / 文楷 / 思源黑），分工见「画面规则」一节，**不随期换**。`style.titleFont` 这个开关留着，只在用户明确要求时用。渲出来数字是方块 → woff2 没加载，看 `kit.tsx` 的 `useFonts`。
- **两期长得太像**：检查发布清单有没有写 STYLE_DNA、photo.json 的 `style` 有没有生效、场景是不是都手写了 box（或者骨架写死的 `grad`）把母版盖掉了。
- **音效单调 / 缺环境声**：让用户按 `工具/音效库/补充音效清单.md` 补，补完 `python scripts/import_sfx.py`；之后才能在分场景表和 photo.json 里写这个环境声。
- **Windows / Mac**：路径和 Python 命令的区别见开头那张表——Mac 用 `python3`，Windows 用 `python`；两边都用 Remotion 自带的 chrome-headless-shell 渲染（新机器先跑一次 `npx remotion browser ensure` 下载；实在下载不了才设 `USE_SYSTEM_CHROME=1` 退回本机 Chrome，那样会有花屏，交付前必须跑 `glitch_check.py`）。Mac 上没有真图时先 `placeholder_photos.py` 出占位图再渲拼图。
