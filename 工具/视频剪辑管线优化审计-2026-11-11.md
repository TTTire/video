# 视频剪辑管线优化审计（2026-11-11）

> **基线**：`ac66023`（2026-11-11 21:22，origin/main 同步）
> **范围**：`工具/aroll-prep`（粗剪 / 转写 / 字幕）、`工具/video-render`（Remotion 引擎 + Python 渲染管线）、`工具/video-broll-maker`（SKILL.md + references）、`工具/validate_package.rb`、交付与剪辑说明流程
> **方式**：只读代码与文档审计（4 路独立审计 + 关键项抽查复核），**未修改任何代码**。下文行号均以该基线为准。
> **用途**：这是给下一轮开发用的「问题清单 + 推荐方案」，不是执行记录。动手时按第 5、6 节顺序来。

---

## 0. 结论

管线能稳定出片、实战经验都沉淀下来了（出镜层、跟脸、实物卡、音效精简、分段渲染、花屏兜底都是踩坑换来的），**但存在三类系统性欠账，优化空间很大**：

1. **规则靠人记，不进代码**——SKILL.md 里 32KB 的「禁用清单」「拼图检查单」全凭执行者记忆和拼图目审，脚本零校验；漏一条就多一轮 8–14 分钟全片重渲。
2. **关键人工环节没有工具**——要点起点表（starts.json）纯手填、讲稿卡改要点后 id 全漂移靠手改、剪辑说明按旧样例手写、交付命名/收尾手工。
3. **代码与文档漂移**——同一套布局有三份真相、photo.json 无 schema（拼错就崩或静默降级）、第 6 期「完整样例」已失真、工程里躺着死代码与 6 GB 残留序列。

**ROI 最高的一件事**：把「禁用清单 + 拼图检查单」变成可执行门禁（`validate_ep.py` + 单一规则源），其次是把 starts.json 和剪辑说明自动化。

## 2. P0：会做错 / 丢数据（先修）

### P0-1 `--frames` 会截短覆盖交付片
- **证据**：`工具/video-render/scripts/render_seq.py:86-87`——`--frames` 只决定渲染区间，但默认输出仍是 `out/<ep>-photo.mp4` 并只编码该段；SKILL.md:289/298 又教「哪章要改，只渲那一章帧区间原位替换」。
- **后果**：照文档做会把交付成片截成一段，且不 `--fresh` 时缺帧列表为空、0 帧重渲，加了 `--fresh` 又会删掉全片帧。
- **改法**：`--frames` 必须显式 `--out`（否则报错）；另加 `--rerender a-b` 只忽略该区间已有帧；帧目录按 photo.json + 代码 hash 失效。
- **收益**：交付片不再被误覆盖，章节替换真正可用。

### P0-2 查花屏内存 O(N)，还可能假成功
- **证据**：`glitch_check.py:18,76` 建 `(N,135,240) float32` 数组，8 分钟片约 1.9 GB、20 分钟约 4.7 GB（项目「时长不设限」）；`render_seq.py:129-132` 不核对搬出的帧数，帧数不等时 `zip` 静默截断，漏检帧既不换也不报。
- **改法**：环形窗口单遍找候选；`same()` 每批 200 帧；期望帧集合比对；headless shell 下默认 `--no-check`。
- **收益**：内存恒定；漏检不再假成功。

### P0-3 时间轴 / JSON 非原子写
- **证据**：`make_timeline.py:149`、`scenes_from_checklist.py:137`、`aroll_face.py:188` 全部 `open(path,"w")` 直写；`src/photo/faces.ts` 是全工程 import 表（`register.tsx:8`）。
- **改法**：统一 `.tmp + os.replace`；faces.ts 加校验/回退。
- **收益**：Ctrl+C、磁盘满时不再损坏工程。

### P0-4 新期默认「实物卡 + 渐显」会被静默丢掉
- **证据**：SKILL.md:123 说 `cardSkin: "tactile"` 是新期默认，但 SKILL.md:68 的 STYLE_DNA 模板没有 `cardSkin`/`textEnter`；`scenes_from_checklist.py:139-154,171-177` 按 STYLE_DNA 重建 style 并整体替换，`setdefault` 只兜 `badge/scale/sfx`；引擎缺省回退是旧档 `st.cardSkin ?? 'flat'`、`st.textEnter ?? 'fly'`（`engine.tsx:480,485`）。
- **现状**：ep9 / AI03 / AI04 / ep10 / AI05 都手动在 STYLE_DNA 里补了这两个字段，所以已出的片没事；但照文档模板写的新期会静默退回扁平卡 + 飞入。
- **改法**：STYLE_DNA 示例补全；更稳的是 `scenes_from_checklist` 合并「新期默认」而不是整体替换。
- **收益**：消除一类看不见的视觉回归。

### P0-5 `SeriesCard` 两 step 的期数 tagline 永不出现
- **证据**：`engine.tsx:501-503`——`byTime = p.steps.length < 2`，`ep7/timeline.json` 的 series 是 `steps:[0,82]`（2 个），走 `p.step >= 2` 分支但 p.step 最大只有 1。
- **改法**：`byTime` 用 `<= 2`，`on2 = byTime || p.step >= 2`；`parseInt(ep.badge)` 加空值保护。
- **收益**：ep7 栏目卡 tagline 恢复。

### P0-6 `center: true` 吞掉显式 `box` 的 y
- **证据**：`engine.tsx:406` `spec.center ? CENTER_BOX : regionBox(spec.box, L.box)`；`ep7/photo.json:228-231`（center + y:240）、`ep6/photo.json:99-100`（center + y:300）全部被忽略；`LAYOUTS.center` 又是另一套值（`:141`）。
- **改法**：`regionBox(spec.box, spec.center ? CENTER_BOX : L.box)`；合并两套 center 常量。
- **收益**：显式排版重新生效。

### P0-7 `BW` 压暗方向反了，且无区域时写死 `grad`
- **证据**：`scenes_from_checklist.py:48` 只按列字母映射（`W→top`），`:124` 取 `reg[1]`——`BW`（整行 + 底）会得到 `top`；`:126` 无区域时写死 `grad:"left"`，把本期 `style.layout` 盖掉。
- **改法**：按「行+列」映射（`BW→bottom`、`TW→top`）；无区域时不写、让母版生效；补 `BL/BC/BR` 映射。
- **收益**：底部字不再压亮图，换母版时行为符合文档。

### P0-8 缺图检查被占位图骗
- **证据**：`import_photos.py:60`、`import_cards.py:60` 见 `os.path.exists` 即算已入库，而 `placeholder_photos.py:17-28` 生成的是同名占位图。
- **改法**：本次导入写 `.imported.json` 记录来源，只认本次导入；`--need` 检查也排除占位图。
- **收益**：占位图不会混进成片。

### P0-9 要点起点表几乎不校验
- **证据**：`make_timeline.py:43` 的 `seconds()` 接受负数、`-01:00`、`1:2:3:4`；只查全局单调（`:92`），不查范围与相邻间隔。
- **改法**：正则只认秒数 / `mm:ss.s` / `h:mm:ss.s`；校验 `0 ≤ t ≤ end`、相邻间隔；报错带要点 id。
- **收益**：录后手填错当场暴露，不再带病渲染。

### P0-10 aroll-prep：剪切清单被无条件覆盖
- **证据**：`tools/aroll-prep/scripts/propose_cuts.py:204-205` 每次都整体重写 `.md` + `.json`；而实际清单是人工改过 `处理` 列的 72 行（含片头/拼接/章间/口误/提示词/片尾等 15 行规则，propose 只产 4 类）。
- **改法**：默认写 `剪切清单.new.md`；`--merge` 按（类型, 起点）稳定 id 保留人工 `处理` 列；补「段缝/章间/数字不符」规则。
- **收益**：不丢人工审查结果。

### P0-11 aroll-prep：切点没落在视频帧上
- **证据**：`cut.py:136-137` 视频 `trim=start={a:.4f}:end={b:.4f}` 与音频 `atrim` 用同一浮点秒，`fps=30` 到 `:140` 才做；视频按帧取整，多段拼接后音画逐段漂移。
- **改法**：`plan_cuts` 里把切点 round 到 1/fps，并打印实际切点。
- **收益**：srt / words / B-roll 与成片严格同基准。

### P0-12 aroll-prep：多条录音笔只取最长一条
- **证据**：`sync.py:349-352` 多条音频时 `sort(key=duration); rec = audios[0]`，其余静默丢弃；实际工作流是手工拼 4 段 wav + 插 30s 静音，丢样时还要手工多段对齐。
- **改法**：`--recorder-dir` 按相机段自动拼接/逐段配对；钟漂拟合作废时按窗分段对齐；多文件时明确报错并列出候选。
- **收益**：去掉每期最易错的手工 ffmpeg。

## 3. P1：每期重复劳动 / 高摩擦

### P1-1 starts.json 纯手填（最大人工头）
- `SKILL.md:207` 要求对照粗剪 srt/words.json 逐条记要点开口；`make_timeline.py:79-97` 只做完整性/单调校验。每期约 30 个要点对 100 段转写，20–40 分钟，且最易错。
- **改法**：新增 `starts_from_words.py`——用 srt/words.json 做要点 vs 转写的字符级对齐 + 停顿边界，输出建议起点与置信度，人工只改低置信项；与 aroll-prep 的 transcribe 打通。
- **收益**：每期省 20–40 分钟。

### P1-2 讲稿卡改要点 → 要点 id 漂移，无 remap 工具
- AGENTS.md 明说「增删要点会让后面的 id 变，场景表跟着改」：发布清单场景表、photo.json 的 `at/until/swap.at`、aroll cues、starts.json 全要手改，错一处就是错位。
- **改法**：`sync_points.py --old <旧卡> --new <新卡>`，按要点文本相似度生成 id 映射（支持人工确认），自动更新 scenemap / photo.json / aroll cues，并提示 starts.json 需重填的 id。
- **收益**：改稿不再全量手跟；这是流程级痛点，建议优先。

### P1-3 剪辑说明手写、样例是旧格式
- `SKILL.md:318` 让「格式照第 6 期」，但第 6 期剪辑说明引用不存在的 `timeline_from_srt.py`、旧合成 `Ep6FxSfx`，出镜表还是「行号」口径；章节帧区间、出镜表、场景表其实都能从 timeline / scene-names / aroll_cues 生成。
- **改法**：`make_editing_notes.py <epN>`：读 timeline.json + scene-names.json + aroll_cues + 成片核验结果，生成章节段表、出镜表、场景起点表、重渲命令；留少量手写区；格式以新模板为准。
- **收益**：交付提速、格式统一、不再复制旧错误。

### P1-4 交付命名/收尾靠手工，且命名有 3 种写法
- SKILL.md:291 `-动画轨+出镜-仅音效-全片.mp4`；:312 `-动画轨-对齐口播-仅音效.mp4`；split_chapters 输出 `-0开头/-1第1章/...`；split_scenes 输出 `剪辑素材-分场景-仅音效`。
- **改法**：`deliver.py <epN> <选题文件夹>` 统一命名 + 拷片 + `glitch_check` + 时长/帧数核对 + 生成剪辑说明 + 打印剩余手工步骤（BGM/字幕/剪映）。
- **收益**：交付零漏项、命名不再漂。

### P1-5 环境自检缺位
- 无 `requirements.txt`（Pillow/opencv/numpy 只在散文里）；ffmpeg 只认 PATH（`_common.py:52-56`）；`setup.py` 不校验 ffmpeg/不预下模型；remotion.config.ts:13-19 只列 Windows/Mac 两个 Chrome 路径；`package.json` 依赖全 `^`、无 engines。
- **改法**：`scripts/doctor.py`（node/npx/ffmpeg/opencv/numpy/字体/模型/Remotion browser/磁盘/中文路径）+ `requirements.txt` + pin 版本。
- **收益**：换机器/新会话一次跑通，不再靠排错。

### P1-6 aroll-prep 实际在用的转写链路没有固化
- 三期 words.json 的 `note` 记录实际做法：能量切句（静音≥0.45s）→ 逐句转写 → large-v3/turbo 双跑核对 → 对照讲稿卡改错字 → 词时间按停顿分段线性校正 → 剪点强制锚点；而 `transcribe.py` 只有一版：固定 INITIAL_PROMPT + VAD 300ms + 单模型。
- **改法**：`transcribe.py` 加 `--split-silence 0.45`、`--cross-check large-v3-turbo`（不一致词写 flags）、`--align-words`（能量起止 + 句内停顿线性校正）。
- **收益**：省 3 遍 ASR 与手工分词对齐；错字校对从通读变查 flags。

### P1-7 改一行也要全量重跑
- `cut.py:217-251` 无 `--plan-only/--preview`，每次改 `处理` 就重解码 12 分钟视频+编码；`sync.py:377-380` 每段都把整条录音笔重测 loudnorm。
- **改法**：`--plan-only` 先出剪辑后音频 + 计划表（秒级）再渲染；loudnorm 测一次复用。
- **收益**：迭代从分钟级降到秒级。

### P1-8 字幕生成不合 AGENTS 规范
- `cut.py:191` 只 rstrip `，,、;；`（句末「。」保留）、`:179-202` 按 20 字硬切、无双语；成品被手工重切（中文 srt 04,222 vs 粗剪 03,946，699→555 行）。
- **改法**：`--srt-style ags`（去标点、按停顿切、留 0.2s 缝）；中英合并成 AGENTS 的双语格式；切句规则与字幕工具共用。
- **收益**：字幕不再二次返工。

### P1-9 SSKILL「每个 gate」缺判据
- 写稿校验只提 `scenes_from_checklist.py`，没提 AGENTS 的 `validate_package.rb`；收料（SKILL.md:203）只有清单；交付（:310）只有复制路径。缺「过不过」的标准：srt/代理时长差 ≤1s、图编号齐、拼图检查单全过、坏帧 0、四段 `--verify` SSIM≥0.98。
- **改法**：文档每个 gate 写「输入 → 输出 → 判据」；判据尽量落到脚本 exit code。
- **收益**：执行者不再靠猜，验收可复现。

### P1-10 冒烟测试没有断言
- `aroll-prep/tests/smoke.py` 只 print、永远 exit 0；依赖 `video-render/out/ep8-full.mp4`；无中文路径、多段拼、多录音笔、残句用例。
- **改法**：核心纯函数单测（`parse_time`/`plan_cuts`/`remap`/`cues_from_segments`）+ 中文目录/4 段拼接用例，加 assert 与退出码。
- **收益**：重构有回归网。

## 4. P2：结构、文档、维护性

### P2-1 重复代码：comp_of 5 份、FPS 30 八处、清单解析 3 份
- `render.py:23`、`render_seq.py:33-38`、`aroll_face.py:30-33`、`new_episode.py:22`、`split_chapters.py:36`；FPS 见 make_timeline/render_seq/aroll_face/aroll_cues/split_chapters 等；清单段+编号正则见 `scenes_from_checklist.py:18-33`、`import_photos.py:21-27`、`import_cards.py:21-27`。缺参一律 traceback。

### P2-2 布局三套真相
- `kit.tsx:237-243` 的 REGIONS/REGION_CENTER、`engine.tsx:134-142` 的 DEFAULT_BOX/CENTER_BOX/LAYOUTS、`:414-415` 又写死 split 的 70/1030/820；`kit.tsx:263-265` GridOverlay 硬编码 670/1250/680，与真实 L 列宽 990、B 行 bottom=270 对不上（`kit.tsx:237-238`）。

### P2-3 类型松、无 schema

### P2-4 引擎过度集中
- `engine.tsx` 546 行：类型（15-105）、富文本（108-118）、20+ 元素 switch（186-366）、场景（371-493）、栏目卡与装配（496-543）。
- **改法**：拆 `schema.ts` / `items/` / `scene.tsx` / `series.tsx` / `build.ts`。
- **收益**：新增元素只动一处，可读性提升。

### P2-5 注册靠手写，且存在重复合成 id
- `Root.tsx:26-57,104-118` 手写 10 期；`new_episode.py:45-55` 字符串替换 TSX（标记缺失时静默无效仍打印「已注册」）；Ep7 同时注册旧 TTS 版和照片版（重复 id）；ep10 占位 timeline（total 60）已注册、`public/ep10/` 不存在；src/ep6 手写版与 JSON 版两套并存。

- **收益**：新增期不漏、不误渲；启动即发现重复。

### P2-6 死代码 / 依赖不干净

### P2-7 性能热点

## 5. 把规则变成门禁：validate_ep.py 应覆盖的检查

把 SKILL 的「禁用清单 + 拼图检查单」翻译成脚本可执行规则，规则存 `工具/video-render/rules.json`（文档只引用，不重复定义）：

| # | 规则 | 检查方式 | 数据来源 |
|---|---|---|---|
| 1 | 字不进字幕区 | 按 layout/box 估算文字底边 ≤ 810（SUBTITLE_Y=820 减余量）；显式 box.y/bottom 与 arollPos 小圆下沿一并查 | photo.json + layout.ts 常量 |

| 7 | 字号不超宽 | 按 region 宽度（L=900/R=860/W=1740）与字号表算字数上限（h88≤12 字等），超宽报「拆句」 | 区域常量 + 字符宽度估算 |
| 8 | 字体分工 | 数字元件不走非数黑体、`song` 一期 ≤2、`quote` 才用文楷、字体总数 ≤5 | items 的 type/font/quote |
| 9 | 出图留白一致 | 场景 box/grad 与出图清单该图「文字放哪侧」一致；组合区域要手写 boxes | 发布清单 + photo.json |
