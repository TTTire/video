# 抖音知识精选选题与结构路由

目标是提高“像素呼吸”知识视频的问题清晰度、证据质量和口播推进感，不承诺流量或精选结果。

## 开始前

1. 先完整读取工作区根目录的 `AGENTS.md`。
2. 写新稿、结构性改稿、改开头、拟标题或写发布文案时，再完整读取 `模板/三重张力五杠杆写稿流程.md`。三件套、独立开头、三章职责、60 秒母稿和删稿流程以这两个文件为唯一来源。
3. 本 Skill 只补充题型路由、贯穿载体、抖音入口、证据方式和平台审读，不另建一套通用写稿流程。
4. 涉及《100个经济学原理》时，先读 `模板/选题库/100个经济学原理.md` 核对正式序号。
5. 只有需要复核对标依据或重新判断模式时，才读 [对标结构样本与证据边界](references/benchmark-structures.md)；普通写稿不重复加载整份样本表。

## 先选一种推进母结构

按观众看完后必须解决的唯一问题二选一：

| 观众的核心问题 | 母结构 | 贯穿载体 |
|---|---|---|
| 为什么会这样，我原来漏看了什么 | 机制解释型 | 一个解释物或一条证据链 |
| 能不能做到，怎样做，哪个更适合 | 实测决策型 | 一个真实任务或一张测试矩阵 |

如果两类都像，以标题和结尾承诺的最终判断为准。另一类只能充当证据，不能成为第二主线。

实测决策型仍只保留一个认知反转，例如“不能只看演示效果，要看它在同一真实任务和约束下是否稳定”；不要为了符合格式硬写“你以为，其实”。

### 机制解释型

适合经济学原理、社会现象、商业机制和认知误区。

可从三种入口中选择一种：

- **日常物件推理**：用一张账单、一笔押金、一件商品或一道菜反复演算。
- **事件或人物推进**：沿关键选择、利益变化和后果推进，不写成履历罗列。
- **调查证据揭示**：先摆出冲突说法或异常数据，再用证据逐步排除解释。

母结构：

`可见异常 → 自然误判 → 用解释物搭最小模型 → 追问暴露隐藏变量 → 证据与边界校正 → 回到开头`

执行要求：

- 解释物必须出现在独立开头、至少两章和结尾。
- 先讲人、物、钱或选择怎样变化，再命名术语；若术语就是主题，亮出后立刻翻译成人话。
- 检索前先写清关键变量的操作定义和结果指标。例如“买得更多”究竟指下单率、最终保留量、净销售额还是利润；不能在正文中混用。
- 证据必须证明隐藏变量存在或足以改变结果，并记录来源、日期、统计口径和不能推出什么。
- 强钩子若省略了条件，必须在第二章完成校正；第三章只解释这些条件怎样限制结论，不再引入新材料。

### 实测决策型

适合 AI 工具测评、横向比较、教程和可复现工作流。

先定义一项真实任务或一张测试矩阵：

- 同一任务、输入和约束。
- 可比性门槛：只比较工作模式、账号档位和目标用途可对齐的候选；7—10 分钟横评通常保留 2—4 个。
- 2—4 个与用户选择直接相关的评价维度。
- 测试前写好基准答案或验收标准，不能看完输出后再改评分规则。
- 产品或模型版本、测试日期和关键参数。
- 原始输出、失败样本和人工修正成本。
- 区分普通瑕疵和硬失败；涉及事实、责任人、金额、日期或安全的错误不能被平均分掩盖。
- 生成结果可能波动时重复测试，并把次数与波动写入边界。
- 使用真实会议、文件或用户数据时，先取得授权并脱敏，记录上传去向和测试后的删除方式。

单产品教程用同一任务的步骤检查点或改前/改后结果，不必硬凑多个产品。

母结构：

`先展示完成结果或关键差异 → 交代任务与评价标准 → 场景—操作—输出—判断的实测循环 → 暴露失败与限制 → 谁适合以及怎样选 → 回到开头结果`

执行要求：

- 独立开头展示结果时，同时交代适用对象或测试条件，不能把最佳样例伪装成稳定能力。
- 第一章锁定真实任务、常见误判和评价标准。
- 第二章在同一任务或矩阵内完成实测；每个单元都按“场景或问题 → 操作 → 可见输出 → 人话判断 → 限制”推进。
- 成功与失败结果都必须在第二章出现。第三章只能根据已展示结果收束适用人群、选择规则和常见坑，不再增加新功能或新测试。
- 若候选不满足可比性门槛，分组说明或退出排名，不强行给总冠军。
- 官方宣传只能写成“官方声称”；没有实际复现时，不能写成作者实测结论。

## 自然追问链

复用写稿流程里的“接力卡”，不新增第二套流程卡。

- 把“章尾自然留下的问题”写成观众真的会问出口的一句话。
- 下一章开头先回答上一问，再暴露下一处缺口。
- 整条稿最多保留三个关键追问；需要新理论、新主例子才能回答的问题移入“不讲清单”。
- 机制解释型可以延迟完整答案，但不能延迟“这件事为什么与我有关”。
- 实测决策型应尽早交代路线图或评价维度，让观众知道接下来会怎样验证。
- 删除只负责报幕的“接下来讲”“再来看”“讲到这里”。

## 精选可能性卡

写长稿前先填卡并排序，不要先堆正文：

```markdown
### 选题名
- 母结构：机制解释型 / 实测决策型
- 入口变体：日常物件 / 事件人物 / 调查证据 / 产品横评 / 单品教程
- 观众此刻的场景：
- 观众原来的判断或选择难题：
- 本期要证明的单一判断：
- 关键变量定义与结果指标：
- 贯穿载体：解释物 / 证据链 / 真实任务 / 测试矩阵
- 自然追问链（最多 3 问）：
- 主证据或实测方案：
- 基准答案、验收标准或硬失败：
- 来源、日期、版本和适用边界：
- 反例、失败样本或不能推出什么：
- 与观众的切身关系：钱 / 时间 / 工作 / 关系 / 风险 / 选择
- 一句带走的判断：
- 3 个标题候选：每个去掉系列编号、标点、空格和英文副题后的中文可见正文不超过 13 个汉字
- 本期明确不讲：
```

优先选择同时满足以下条件的题：入口可见、任务单一、证据可回溯、因果或测试条件成立，并能给观众一个具体判断。

用户若只要选题或结构，可以先交“暂定结构 + 待核事实清单”，无需假装已经完成完整研究；进入逐字稿前仍须按 `AGENTS.md` 完成案例研究或实测设计。

## 标题与前 10 秒

先选与题型匹配的入口，不固定套一种情绪：

- **痛感式**：具体处境 → 已发生的代价或误判 → 值得继续看的判断。
- **异常式**：物件、数字或结果冲突 → 自然疑问 → 本期会揭开的变量。
- **结果展示式**：先展示完成态或关键差异 → 交代适用对象与条件 → 本期怎样验证。

前 10 秒至少完成三件事：让观众看见对象或结果，知道自己的旧判断或选择难题，并得到继续观看的理由。

标题只承诺一个问题的解释或判断，不照搬对标账号的“一口气了解”“最强”“天花板”“神”等标志性包装，也不使用正文无法兑现的刺激结论。视频主标题、3 个推荐标题和封面标题去掉系列编号、标点、空格和英文副题后的中文可见正文都不超过 13 个汉字；章节标题不受此限制。

## 证据与边界

- 机制解释型优先使用权威或原始解释、真实公司或政策、研究数据、历史事件和可复现观察。
- 实测决策型优先保留原始输入输出、版本、参数、失败样本和修正成本；横评必须同条件。
- 有客观答案的任务先制作人工核验基准；没有唯一答案时，先定义可观察的验收标准。
- 不可比的版本、模式或套餐不放进同一排名；随机输出只测一次时，必须明确这是单次观察。
- 生活化示意只翻译已经核实的机制，必须明确是示意，不能替代主证据。
- 边界不是结尾免责声明，而是结论成立的条件。条件不足时，降低结论强度。
- 数字必须核对它是单条作品数据、账号累计数据还是搜索摘要；无法回到原页时不使用。
- 跨平台同题视频不能默认是同一剪辑。标题、日期、时长、开头与结尾未核对一致时，只能作为创作者长口播方法的代理，不能给出抖音版精确时间点。

## 抖音增量审读

通用结构与三件套验收按写稿流程执行；本 Skill 只追加检查：

- 是否只选了一种母结构，另一种没有变成第二主线？
- 解释物、证据链、真实任务或测试矩阵是否贯穿，而不是中途换题？
- 三个以内的追问是否形成接力，下一段是否真的回答上一问？
- 强判断是否有直接证据，且版本、日期、口径、反例或失败结果已记录？
- 标题、前 10 秒和结尾是否兑现同一个承诺？
- 视频主标题、3 个推荐标题和封面标题的中文可见正文是否均不超过 13 个汉字？
- 实测稿是否展示同条件输出与失败，而不是复述功能表或官方宣传？
- 结尾是否回到开头对象或结果，只提高半层判断，没有另开理论？
- 是否只借鉴问题设计、证据结构和节奏，没有复制他人的逐字表达、口癖或人设？

三件套完成后运行：

```bash
ruby 工具/douyin-knowledge-selection/scripts/validate_package.rb "进行中/选题文件夹"
```

该脚本只检查独立开头、三章、剪映版和发布清单等机械一致性，不能替代事实核验、实测复现和朗读审读。不要把母结构标签、研究卡或来源注释写入口播稿，否则它们会被视为口播正文。

## 边界

- 不声称某种结构必然带来高赞、完播、流量或精选。
- 不把搜索摘要、自动字幕或第三方拆解称为创作者原始口播稿。
- 不自动发布、评论、购买流量或改动无关脚本。
- 若用户要求对标，只学习结构功能，不复刻具体措辞、案例排序、画面或人设。
