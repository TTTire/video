# 02-榜单排名攀升

状态：粗做。参考视频和出处在 `参考/`。

默认横屏 1920×1080，240 帧（8 秒），30fps；也能出竖屏 9:16。合成 id 是 `02-榜单排名攀升`。

一张榜单网页斜着怼到镜头前，高亮的一行从榜单底部一路往上爬、把别人一行行越过去，分数往上数、底下长出进度条；最后闪白，镜头拉远露出整个榜单。适合“谁排到了第几”的揭晓。

参考是 motionface 片段「排名攀升动效」`8850561c-1ae6-4f37-97a7-4f2032acf773`，一段竖屏的、别人成片的录屏（出处见 `参考/来源.txt`）。竖屏是照它复刻的；横屏没有参考，网页按宽屏重新排过，镜头的高低、倾角照竖屏量出来的曲线按画面高度换算。

动效顺序（帧号）：第 4 帧高亮行从左上角斜着进场、往下滑 → 第 34 帧起往上爬：第一格用 10 帧，接着第 48、52、56、60 帧每 4 帧到一格，最后两格各用 12 帧，第 84 帧停在第一行后面 → 分数第 17 到 40 帧从 1400 数到 1496，进度条第 40 帧起长到拉远结束 → 第 88 帧起下面的行给它让出一格 → 第 155 帧起虚化，第 162 到 166 帧发白 → 第 172 到 228 帧拉远，之后定住。

对照图在库根目录的 `out/02-榜单排名攀升/对照/`：三张是竖屏版和参考的并排（左边参考、右边本模版），另有一张横屏的总览图。

## 适合 / 不适合

- **适合**：某一家、某一个模型、某一款产品在榜单上名次上升的揭晓；榜单八到十一行、每行两三栏数。默认横屏（YouTube），要发抖音、Shorts、Reels 就切成竖屏。
- **不适合**：排名下降（动效只有往上爬）；榜单行数和默认差很多（页面是照十一行排的，列宽、行高不会自动适应）；这一期要放真实数据的，数字得自己核实，默认值没核实过。

## 用法

在库根目录（`工具/remotion模版`）跑：

```bash
python3 scripts/render.py 02                 # 横屏，默认内容（参考视频的原样）→ out/02-榜单排名攀升/默认.mp4
python3 scripts/render.py 02 竖屏            # 9:16，镜头和版面照参考 → out/02-榜单排名攀升/竖屏.mp4
npm run studio                               # 左边挑 02，右边改参数；orientation 一改，画面大小跟着变
python3 scripts/render.py 02 出片.mp4 自己的参数.json   # 用自己写的参数
```

出片时间：横屏约 1 分钟，竖屏约 2 分半（都带着动态模糊）。先调内容时可以把 `motionBlur` 关掉，快很多，定稿再打开。

榜单网页本身是用 HTML 排出来的，不是原作者的截图，所以每一格文字都能换。

## 运动是怎么做顺的

第一版看着有点顿，2026-11-26 改过，以后别的模版也照这样做：

- 所有关键帧曲线（卡片的高度和倾角、镜头的放大、拉远的进度）都是速度连续的平滑曲线（共用的 `src/shared/curve.ts`），拐点处不再变速，进场和拉远都从静止起步。
- 爬升是一口气滑上去的：起步加速、中间匀速、最后减速停住。参考里是每 4 帧越一行的顿挫节奏，越过每一行的时刻没变。第 34 到 84 帧高亮行每帧的速度变化不超过 3 像素（横屏）。
- 页面动得快时带动态模糊，相当于 180° 快门：在前后半帧里多采几个样叠在一起，静止的帧不多采。采样如果还不够密（拉远最快的那几帧），补一点模糊把台阶揉平。

## 参数

字段说明写在 `schema.ts` 的 `.describe()` 里，Studio 面板会直接显示。要点：

- **orientation**：`横屏`（默认，1920×1080）或 `竖屏`（1080×1920）。
- **motionBlur**：带不带动态模糊，默认带。
- **rows**：榜单，从上到下。每行有机构名、型号（名字下面那行等宽小字）、分数、浮动区间、Model Rank、Rank Spread，以及行首小方块里的字符和它的颜色（方块里只能放一两个字符，参考用的是各家 logo）。
- **highlight**：高亮的是第几行（从 0 数）。把它写在它最后停下的位置上。
- **climbFrom**：它从第几格开始往上爬（不算它自己；它一上来压在这一行上面）。默认 8，就是压在倒数第二行上。它不能大于行数减二。
- **countFrom、countAt、countEnd**：分数从多少数到多少（数到这一行自己的分数）、哪几帧在数。
- **rowAt**：高亮行开始出现的帧。爬升的每一步都从它起算。
- **barAt**：进度条开始长的帧，一直长到拉远结束。
- **flashAt、zoomAt、zoomEnd**：虚化和发白从哪一帧起；拉远从哪一帧到哪一帧。参考的拉远是 56 帧，改了长短会等比伸缩。
- `title`、`badge`、`description`、`meta`、`headers`：网页上的大标题、旁边的标签、说明、带图标的小字、表头的五列。

镜头的高低、倾角和页面放大这几条曲线（`Template.tsx` 里的 `ENTER_Y`、`ENTER_ANGLE`、`NEAR`）是照这份榜单量的。行数、行高不变时只换文字不用动；想让爬升更慢，改 `climbCurve` 里每格的帧数，同时把它后面的几个帧号往后挪。

## 和参考不一样的地方

- **默认内容是参考视频的原样**（一个 AI 模型榜单网页），只为逐帧对照用，这些数字没有核实过。
- **横屏没有参考**：网页是照竖屏那一套的疏密重新排的，行高从 74 收到 68；近景里高亮行带着名次、名字、分数、进度条一起放大，右边两栏留给拉远以后看。
- **近景里各行在画面上的大小**：参考里离镜头近的那几行明显大一些，镜头是绕着榜单走的；模版用的是“整页倾斜再转一个角度”这一种镜头，各行均匀。所以同样大小的画面里模版能看到更多行，画面上方会露出网页的标题栏，参考里看不到。
- **高亮行自己**：模版让它比邻行大（进场 1.4 倍，落定 1.2 倍）。参考里落定以后它的字反而比邻行略小、整行偏左约 100 像素；进场头 10 帧参考的卡片很薄而字很大。这两处没有复刻。
- **进场的倾角**：参考头 16 帧量出来有来回晃（第 8 帧 −17.6°、第 16 帧 −13.9°），那是运动重影造成的，模版抹平成一条单调的曲线，这两帧和参考差 2° 到 3°。
- **竖屏第 16 到 40 帧榜单下面那条页面底边**：参考里它紧贴着高亮行，末帧的底边却在榜单下面近一行处，前后对不上。模版按末帧的页面做，这一小段没有那条底边。
- **没做**：四角的暗角、各家真实的 logo。

对过的（竖屏版对参考）：高亮卡片的中线高度和倾角，在第 44 到 156 帧的 8 个关键帧上高度差不超过 5 像素、倾角差不超过 0.4°；进场段（第 8 到 36 帧）高度差 15 像素以内；拉远过程中（第 186 到 220 帧）比参考低 16 像素上下，慢了一两帧；每次越过的帧号，第 44、48、52、56、60、84 帧两边都压在同一行上；末帧各行位置基本重合。量法是 `python3 scripts/measure/band.py 参考/参考视频.mp4 8 239 1 --对比 out/02-榜单排名攀升/竖屏.mp4`。粗做阶段没有逐字校准，上面各条差异留到精修。

## 文件

```
index.ts            对外的五样东西：默认画幅、按参数定画幅（sizeForProps）、组件、参数定义、默认值
Template.tsx        makeView：某一刻画面该是什么样（镜头怎么求、几张平滑曲线、模糊和发白）；Template：叠采样出动态模糊
camera.ts           透视镜头，以及两个求解：页面转多少度才斜成某个角度、镜头跟到多高
Page.tsx            榜单网页：横屏、竖屏两套版面（Layout）和同一种结构；竖屏的坐标量自参考第 239 帧
schema.ts           参数定义和默认值
示例-竖屏.json      切到竖屏的示例
参考/               参考视频（mp4 不进 git）和 来源.txt
```

字体都注册在库的 `src/shared/fonts.ts`：Archivo 可变字体（页面文字），加上 npm 包 `@fontsource-variable/jetbrains-mono`（分数、型号）和 `@fontsource/instrument-serif`（网页大标题）。三款都是 SIL Open Font License。画面用的是库的 `Grain`（颗粒），不开铺底照片。
