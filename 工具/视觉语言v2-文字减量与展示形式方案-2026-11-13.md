# 视觉语言 v2：文字减量与展示形式方案（2026-11-13 定稿，11-13 评审后修订）

> 定位：这是**第二版计划**，只管画面表达层（写稿叠字 + 渲染形式）。它不改第一版《视频剪辑管线优化方案》的内容，但**不独立于它**：渲染层挂在第一版的阶段 5，校验层要等第一版的 `validate_ep`（见 §5）。方向来自用户确认：画面文字偏多，减字 + 换展示形式；证据类内容换成「原文档展示」（文件高亮风格）。图片素材量允许增加。
>
> 本次修订改了什么（评审 2026-11-13）：补了手机上看得清的硬指标、文档页的安全区、「8 秒」规则怎么改、数字动效的用法边界、tagwall / pyramid 的尺寸和字量、入库方式、AGENTS 要改的条目、试点怎么做；现状数字按统一口径重算。

## 0. 现状与目标

- **现状实测（AI05，`src/ai05/photo.json`，口径见 §4「怎么数」）**：26 个照片场景，平均每场 4.3 个文字元素，最多 8 个（cd）；到场景结束时同屏超过 4 个的有 9 场，最多 7 个（kimioct：三行时间线 + 四行说明）；只有 5 场用了 `until` 收字，其余的字到场景结束才消失。
- **目标**：字变少、形式变多——证据换原文档、数字换图表/实物、罗列换卡片墙、复述口播的字删掉。
- **不变的红线**：质量不下降（判据见 §6）；事实底线不松（引用必须可回溯到事实核对）；出镜层照旧。

## 1. 减字三原则（调研归纳）

1. **文字只当标签**：机构名、数字、一个词可以上屏；**句子让口播说**（回形针式，黑底白线图标 + 标签字）。例外：开场钩子那一句保留，不然前几秒画面上没有信息。
2. **信息分两层**：画面只放「可辨认的最小证据」，完整标题 + 链接放事实核对和 YouTube 简介（掘金《短视频资料来源怎么标注》方法论）。抖音文案里的外链点不开、还可能被当成导流，只写来源名。来源要直接支持那一句话，截图裁切不改原意。
3. **同一视觉元素反复登场**：公司/人物做成徽章全片复用；同一张信息图多次出现、每次状态变化（变灰/盖章/变色）——靠重复建立视觉词汇，不靠每次重新写字（小lin说式）。

## 2. 按文字类型逐类替换（核心表）

| 现在的字 | AI05 例子 | v2 换成 | 素材增量 |
|---|---|---|---|
| 证据/引用 | 客服原话卡、道歉信要点卡、报道要点 | **document 元素**：原文页滑入 + 高亮 + 聚焦放到能读 + 短标签（机构/资料名/年份）；英文原文配一行中文短译；完整链接留事实核对。**拿不到干净原图时退回 `paper` 卡 + 短标签**（规则见 §2b） | 原文页截图 2–4 张/期 |
| 数字 | `¥1908`（已经是 big）、`$19.95 / 月` 写在句子里 | **固定的数**（价格、年份、一个总量）用 `big` / `slam`，一期 `slam` 不超过 2 次；**来源给了前后两个值**（额度 100%→0、AOL 14→32 分钟）才用 `odometer` / `flap` / `fill` / 柱状图。没有起点值的数不做滚动——里程表从 0 滚上去会经过从没存在过的中间值，画面等于在说「涨了」 | 部分需实物小图 |
| 罗列 | 配给场景：发布清单写的是 stack 三张，photo.json 实际是 5 行字（限额 · 排队 · 停卖 · 少给一点 + 两行解释） | **tagwall 四宫格大卡**（尺寸见 §2b）+ 一个词「配给」 | 图标（跨期复用） |
| 层级/结构 | 用文字描述阶层 | **pyramid 层级图**（逐层弹出 + 图标；每层只有一个 ≤ 4 字的标签，可加一个数） | 图标 |
| 因果链 | stack + 解释行 | 只留 stack 三张，解释让口播说 | — |
| 人名/公司 | 每场重复写名字 | **徽章**（圆形 + 图标/字卡）反复登场 | 图标 |
| 对比 | 两张并排 tab 卡（已克制） | 保留，颜色语义化（teal/coral） | — |
| 复述口播/疑问句 | 「割韭菜吧？」「拿什么管住你？」 | **直接删**，出镜 + 口播扛；开场钩子除外 | — |

### 2b. 展示形式的硬约束（评审新增）

**手机上看得清是底线。** 抖音信息流里 16:9 画面缩到 0.56 倍（`references/douyin-safe-zone.md`），画面上 44 px 的字到手机上只有 25 px。所有新形式按 1920×1080 画布算，字高不低于现有最小的小字 `t`（44 px）。

- **document**
  - 聚焦不是 1.1 倍的轻微放大，是**放到高亮句能读**：聚焦后高亮句的字高 ≥ 44 px（放大倍数按截图实际字高算，上限 4 倍）；截图字太小放不到就加一行摘句（`excerpt`，`h` 档）。英文原文必配一行中文短译（`t` 档）。
  - 文档页在右侧时占 x 1020–1620、全屏时占 x 90–1620；页面不进字幕区（y > 820）和抖音图标区（x > 1620），滑出这两个区的部分压暗。有出镜层的期：右侧文档配右上小圆没问题（小圆在 x ≥ 1640）；全屏文档时小圆放左下（`arollSide: left`）或 `hide`。
  - 高亮色是文档段里**唯一的强调色**：短标签、摘句、译文只用白 / dim，不用金。高亮色取本期 `gold` 的半透明（用户 2026-11-13 确认；AI05 是青、ep9 是粉、ep10 是柠檬黄），不另引入固定的黄色。
  - 什么时候用 document、什么时候用 paper 卡：能拿到**干净、可读、可回溯**的原图（无水印、无登录墙、裁切后原意不变）才用 document；只有转述、付费墙、X 帖子截图模糊这类情况用 `paper` 卡 + 短标签。同一条来源不要既出 document 又出 paper。一期 document 1–3 处，paper 仍然最多 1 次。
  - 页面滑动、高亮、聚焦都算「画面变化」（见 §4 的 8 秒规则）。
- **tagwall**
  - 画面可用宽度只有 1530（x 90–1620，右侧 300 留给抖音图标）。两列卡每张 **≤ 740 宽、间距 50**（原稿写的「≥ 780」放不下，而且引用的「数字卡 780」从来没生效过，卡实际都是 900）。高度：两行卡 ≤ 325 高、间距 40，开黑边的期再减 20。
  - 标签字走 `h` 88 档（手机上约 49 px，满足原稿「不小于画面宽度 4.5%」= 86 px）；每张卡一个图标 + 一个 ≤ 6 字的标签，不写第二行。
  - tagwall 出场的场景不放别的大字；四张卡算 4 个文字元素，正好顶到同屏上限。
- **pyramid**：层数 ≤ 4；每层一个 ≤ 4 字的标签 + 可选一个数，没有翻译行、没有描述行（描述让口播说）；逐层弹出时只有当前层的标签亮，其余层压成 dim。
- **徽章**：直径 ≥ 160，名字 ≤ 4 字；同一个人 / 公司全片一个徽章，不换样。
- **数值动效**：沿用 SKILL 的验收标准（每一帧都是合法数据状态），所以只有来源给了起止两个值才能滚。

### 图标清单（第二批依赖，要这些）

图标的作用：让画面用「图形」代替句子表达语义——tagwall 每张卡配一个图标、pyramid 每层配一个图标、徽章 = 图标 + 名字。全部**单色线条风**（stroke 1.5–2px、圆角统一、透明底、无文字、可商用、SVG 能改色），一组约 25–35 个。

| 组 | 图标 | 用在哪 |
|---|---|---|
| 钱与市场 | 硬币、钞票、钱包、购物车、商店、银行大楼、天平、价格标签 | 徽章、pyramid 财富层、tagwall、graph 节点 |
| 人 | 单人、人群、排队、握手、喇叭 | 社会阶层、排队场景 |
| 生产与算力 | 工厂、齿轮、芯片、服务器机架、灯泡、电池 | AI 徽章、算力层、供给侧 |
| 规则与限制 | 锁、沙漏、禁止、放大镜、红绿灯 | tagwall「限额/排队/停卖/少给」、政策场景 |
| 结构与变化 | 房子、写字楼、网状连线、上/下/循环箭头、金字塔层块 | 因果、涨跌、网络效应、层级 |

**来源：只从一家取**，整组线宽和圆角才一致。首选 Tabler Icons（MIT，量最大、线宽可调）；缺的再从 Lucide（ISC）补，补的要改成同样线宽。Phosphor / Feather 不混用。

估算：每期图片素材约 19 张 → 23–26 张，可接受。

## 4. 配套改动（写稿层 / 渲染层 / 校验层）

**写稿层（broll SKILL + checklist-format.md；讲稿卡格式不改）**
- 叠字规则改为**按类型配字**：证据、数字、结论才上字；讲述性要点不上字，用出镜 full / half、换图或图表变化来承担画面变化
- 「禁止 8 秒无字」改成「**禁止 8 秒无变化**」：变化 = 出字、收字、换图 / swap、图表或数值动效、出镜切换、文档页滑动 / 高亮；照片缓推不算。再加一条正向要求：**每章留 1–2 处呼吸段**（无字 + 底图缓推 + 出镜，每处 3–5 秒，本来就在 8 秒之内）
- 分场景表的叠字列可以写展示形式名，写法 `[document#3]`（# 后是事实核对条目号）、`[tagwall]`、`[pyramid]`、`[徽章:Kimi]`。现在的 `scenes_from_checklist.py` 会把它当成一条字生成进骨架，填 photo.json 时手工换成元素；第一版方案阶段 2 改脚本时让它识别方括号
- 证据场景挂短标签：机构 / 资料名 / 年份，和事实核对条目号对应；事实核对那一条的「用在」要写到这个场景的要点

**怎么数「文字元素」**（同屏上限和现状统计都按这个）：每条 `h` / `t` / `tag` / `big` / `stamp` / 数值动效算 1；`stack` 每张卡算 1；`photorow` 每张卡算 1；`graph` 每个节点算 1；tagwall 每张卡算 1；document 整页算 1、短标签 1、摘句 / 译文各 1；卡片的分类签、字幕不算。同屏 = 同一时刻画面上可见（`until` 收掉的不算）。

**渲染层**：document、pageflip（硬翻）、pyramid、tagwall、徽章 skin、units 变体——设计见 [references/document-highlight.md](工具/video-broll-maker/references/document-highlight.md)，挂第一版方案阶段 5，实现时与本计划合并执行。新增一个入库脚本 `import_docs.py`（D 编号、原比例不裁、不缩到 2560 以下 → `public/<ep>/docs/`）；`import_photos.py` 只认 S 编号、会裁成 16:9，不能拿来入文档页。

**校验层**（都挂在第一版方案的 `validate_ep`，它不存在之前靠拼图人工查）
- 同屏文字元素 ≤ 4（warn 级）
- document 引用必须有 fact 号且存在于事实核对；事实核对该条的「用在」含这个场景（已设计）
- 8 秒无变化（hard）；呼吸段每章至少 1 处（warn 级）
- document 高亮句聚焦后字高 ≥ 44 px、不出安全区（warn 级）

**AGENTS.md 要改的条目**（动工前先改，不然文档页违反现行硬性要求）：
- 「画面与素材清单」一节：「所有图不含任何文字，16:9，宽度 ≥ 2560」加一条例外——文档页截图 `D01`… 允许原文文字、保持原比例，宽 ≥ 2560
- 「事实底线」一节：加一句「文档页截图裁切不改原意，引用句对应事实核对条目」

## 6. 试点与「质量不下降」怎么判

**试点期：10/100 消费者剩余**（`进行中/10-100-消费者剩余-半价买的手机真赚到了吗/`，ep10），用户录完再开始。AI05 已发布，不重渲，也不在它上面做试点。

**怎么做**：
- 录前不用改：第 0 批不改讲稿卡格式；出图清单不受减字影响，照原样出图。
- 收料后、填 photo.json 之前，按 §4 的第 0 批规则改发布清单分场景表的叠字列：讲述性要点删字，证据挂短标签，每章标 1–2 处呼吸段。第一批（document）那时还没做好的话，证据用 `paper` 卡 + 短标签。
- 之后照 SKILL 现行流程走：骨架 → 拼图 → 40 秒小样 → 全片。字号、卡片、配色和禁用清单的其余各条都不变。

**判据**（每条都要过）：
1. 手机上看得清：40 秒小样和含证据 / 数字的场景截图（`render.py ep10 still <帧号>`）放到手机上，按抖音信息流的大小看（竖屏、视频不全屏），短标签、数字、证据都能读
2. 没有 8 秒无变化的段；每章有 1–2 处呼吸段
3. 同屏文字元素 ≤ 4 的场景 ≥ 90%（AI05 是 16/25，64%）
4. 证据不丢也不多：事实核对里每条用到的来源，在它「用在」的场景里画面上有短标签、paper 卡或 document；画面上的每个数字和引用都能在事实核对里找到
5. 禁用清单其余各条零违例

**结果**：全过 → 第 0 批规则正式写进 SKILL 和 checklist-format.md（替换「8 秒无字」等），之后每期照新规则；哪条没过 → 改那条规则，下一期再试。
