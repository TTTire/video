# 视频剪辑管线优化方案（2026-11-12）

> **定位**：替代《视频剪辑管线优化审计-2026-11-11.md》（已删除；审计原文见 git 提交 `e2aae4d`）。本文 = ① 流程层优化点（AI05 实证，全新）+ ② 技术修复清单（承接审计，按评审意见修正）+ ③ 实施路线与验收标准（升级版）。
> **基线**：`36c7927`（AI05 素材 pull 后）。**目标**：管线产出的视频质量不下降；同时把每期重复劳动和「靠人肉兜底」降下来。

## 0. 结论

审计确认的三类欠账仍成立，全部保留：

1. **规则靠人记，不进代码**——32KB 禁用清单 / 拼图检查单全凭记忆与目审，漏一条多一轮 8–14 分钟全片重渲。
2. **关键人工环节没有工具**——starts.json 手填（每期 20–40 分钟）、要点 id 漂移靠手改 5 处、剪辑说明照旧样例手写、交付命名 3 种写法。
3. **代码与文档漂移**——布局三套真相、photo.json 无 schema、第 6 期样例失真、死代码与渲染残留。

AI05 实地调查新增一层：**流程层有 7 个优化点（第 1 节），多数成本极低**，且解释了「为什么每次 pull 下来都要先问一圈缺什么」。

质量底线靠三个机制兜住（评审新增，原审计没有）：

- **黄金基线**：任何引擎 / 脚本改动前，先用定稿一期按改动前代码渲好留档；改后对比 + 「预期差异清单」逐项签字（1-F / 3.2）。
- **分层门禁**：完整性规则硬失败，样式规则默认 warn 且可豁免（3.1）。
- **高风险项单列**：多录音笔自动拼接带同步 QA 门，不进「顺带」项（阶段 4）。

**ROI 最高三件事**：`check_ep.py`（缺件可见性）→ `validate_ep.py + rules.json`（规则门禁）→ 录后回写（文档与成片一致）。

### 0.1 与现状流程的区别（一句话版）

流程步骤不变（写稿 → 出图 → 录制 → 粗剪 → 渲染 → 交付），变的是「靠人记、靠人查、错了重渲」换成「机器把关、机器兜底」：

| 场景 | 现在 | 改后 |
|---|---|---|
| 换机器 / pull 之后 | 人肉核对缺了什么媒体，缺件要问一圈 | `check_ep.py` 一条命令出缺件清单 + 搬运清单（1-A） |
| 改画面 / 引擎 | 整片重渲，画面对不对全凭目审 | 先渲黄金基线，改后逐场景对比 + 差异清单签字，清单外差异一律算 bug（1-F） |
| 守规则 | 禁用清单靠执行者记，漏一条 = 多一轮全片重渲 | 渲染前 `validate_ep` 自动校验：完整性硬失败、样式规则警告且可豁免（3.1） |
| 跳点 / 改稿 | starts 手填、要点 id 漂移手改 5 处、跳过的要点文档里还挂着 | 机器出建议稿、自动映射 id、录后回写，文档与成片一致（1-B / P1-1 / P1-2） |

用户每期的实际动作（出图、录制、看拼图提意见）不变，省掉的是查漏、重渲和来回对账。

## 1. 流程层优化点（AI05 实证）

每条：现状痛点（AI05 实测证据）→ 做法 → 验收。

### A. check_ep.py：缺件可见性 + 搬运清单（最优先）

- **痛点**：git 只带小文件（`.gitignore` 排掉 `*.mp4/*.mov`、`public/`、`out/`），媒体靠手工拷。AI05 pull 后缺 9 类文件（原片 MOV × 4 + 录音笔、同步 mp4、粗剪成片 mp4、public/ai05 资产、BGM、封面、双语字幕等），broll SKILL「换机器重渲」一节只讲了「有文件之后怎么做」，没讲「怎么知道缺哪些」。
- **做法**：`python scripts/check_ep.py <epN>` 列出该期全部媒体依赖：git 里有 ✓ / 本机缺 ✗，注明「缺了会卡在哪一步」「必需 / 可选」「在哪台机器」。输出本身就是搬运清单。
- **验收**：新机器 pull 后跑一次，10 秒内知道能不能开渲、要拷什么。

### B. 录后回写：跳点 / 改说同步回讲稿卡与发布清单

- **痛点**：AI05 讲稿卡 3.5「自己撞上限额」没录进成片（剪切清单 3.4 结尾直接接 3.6；starts `3.5==3.6==05:43.30`；成片字幕 05:27 直接跳 05:43），但讲稿卡、发布清单场景 28、事实核对 17 条还挂着。make_timeline 机械上处理正确（0 时长场景跳过），文档却漂移。
- **做法**：make_timeline 已知道哪些要点时长 = 0，直接输出「跳过的要点清单」；执行者据此在讲稿卡标 `⊘跳过`、发布清单场景表标「跳过」、事实核对同步。临场改说的内容（AI05：AOL「19.95 美分→美元」、拼接口误等，剪切清单里有记录）同样回写进卡。同时把「跳过的要点填和下一条一样的时间」这个约定从 make_timeline docstring 移进 broll SKILL 收料检查正文（G）。
- **验收**：讲稿卡 / 发布清单与成片逐条一致；下期写稿不再引用没播出去的事实。

### C. 环境声只能引用真实存在的 variant

- **痛点**：AI05 分场景表写了「办公室」「咖啡馆」，[工具/音效库](工具/音效库) 只有 商场 / 街道夜晚 + 通用 ambience；引擎找不到 variant 就在同类随机兜底 → 氛围声与画面错位，且静默。SKILL.md:118 让人按 8 个名字写，和实际库存矛盾。
- **做法**：① 分场景表环境声列只写已导入的 variant，要新氛围就在出图清单加一行「补音效」任务（补充音效清单里已有这个约定，只是没人执行）；② 收料 gate 加判据：photo.json 引用的 variant 必须已入库，缺就报错，不随机兜底。
- **验收**：AI05 的办公室 / 咖啡馆两个场景，要么补录 variant，要么改回现有名字，渲染不再随机。

### D. 双语字幕合并进流程

- **痛点**：AI05 中 / 英各 139 条、时间轴完全一致，但 AGENTS 要的「双语合并版 srt」不归任何一条命令管，永远断在中间态。
- **做法**：合并动作并入 deliver.py（P1-4）或独立一行命令，字幕环节收尾即出双语版。
- **验收**：字幕完成 = 双语 srt 已存在，不留「以后再合并」。

### E. 剪切清单定稿 / 已执行状态

- **痛点**：AI05 剪切清单 72 行手工决策（拼接、口误、提示词剪掉、章间留白）是整期最贵的资产；propose_cuts.py 会无条件整体覆盖（P0-10），清单无「定稿」标记，成片实际时长（365.6s）没有写回（头部还写着「成片约 06:05.598」）。
- **做法**：清单头部加状态行（`状态: 定稿 / 已执行`）；cut.py 执行后自动标「已执行」并把实际成片时长写回。与 P0-10 的 `--merge` 一起实现。
- **验收**：复剪时清单可追溯，人工决策不丢。

### F. 黄金基线约定

- **痛点**：任何引擎改动都会改变已批准画面（P0-5/6/7 修复本身就会让老期重渲变样），方案没有「改动前后画面对照」机制，质量下降无从发现。
- **做法**：写进 broll SKILL 渲染阶段开头：改动引擎 / 渲染脚本前，用已定稿一期按改动前代码渲全片（或每场景代表帧）留档；改后同场景重渲对比 SSIM + 人工 A/B，产出「预期差异清单」（如「ep7 栏目卡 tagline 恢复」），清单外差异一律算 bug。
- **验收**：AI05 是第一个基线（阶段 0）。

### G. 流程小项（顺手做）

- 剪辑映射 json 的源路径是 Windows 绝对路径（`E:\视频脚本\...`），换机器失效 → 生成时改相对路径或只存文件名 + 时长。
- broll SKILL 的「分工」表与收料检查把 A / B / C / F 的新步骤补进去。

## 3. 门禁与质量保障机制

### 3.1 validate_ep.py + rules.json（分层）

- **完整性规则 hard-fail**（exit 非 0，可挂渲染前）：资产存在（占位图不算）、要点 id 对齐（scenemap / photo.json / aroll cues × 讲稿卡）、起点表完整合法、章节卡行合法、出镜 cue 越界。
- **样式规则默认 warn**：stagger ≤2、gradient ≤1、slam 1–2、solid ≤2、paper ≤1、颜色语义、字号超宽、字体分工、连续三场不同图、留白一致、小圆安全区。photo.json 留豁免位 `styleWaivers: ["slam-count", …]`——风格在演进（tactile 2026-10-29 才成新默认），门禁不能变成创作牢笼。
- **验收**：拿第 6 / 9 / AI05 三期跑，种入 P0-5/6/7 类型已知问题要求**全检出**；干净期 0 误报。「0 误报」不作为把规则逼松的理由——规则价值用「种子检出率」衡量。
- **校准**：字符宽度估算模型先拿真实渲染对照校准再上线，避免误报逼着拆句。
